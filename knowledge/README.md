## 知识库与 skill 的分工（方案 6.1 / 6.3）

**这是最容易被写错的地方，所以放在最前面：**

| | 放什么 | 判断标准 |
| --- | --- | --- |
| **skill** | 流程、决策树、检查清单、反模式、带推理的范例 —— **「怎么做」** | 每条内容必须能**改变模型的下一个动作** |
| **知识库** | 概念定义、标准条款、论文结论、样本模型、项目文档 —— **「是什么」** | 陈述性事实，供检索引用 |

一句话：**skill 管怎么做，知识库管是什么。** 把教科书定义抄进 skill 是典型的无效写法——
占着宝贵的上下文，却不改变模型的任何动作。

## 规划中的目录结构

对应技术方案 8.4 的约定：

```
knowledge/
├── samples/        # 参考样本模型（IR + SysML v2 成对存放）
├── project/        # 项目需求、总体架构、功率链资料、电池与桨的测试数据表
└── standards/      # 官方文档要点、论文摘要
```

| 子目录 | 计划入库内容 | 来源（方案 7.4 的可信度排序） | 量级 |
| --- | --- | --- | --- |
| `samples/` | 老师给的 SysML v2 样本模型；官方 pilot implementation 示例；本项目标杆案例（先放 `examples/golden-coaxial-power-chain/` 的副本或引用） | ① 老师样本 → ② 官方示例库 → ④ 自建 | 3~5 份 |
| `project/` | 任务书与需求文档、总体架构说明、功率建模材料、电池与桨的测试数据表、会议纪要 | ③ 项目已有资料 | 十几份 |
| `standards/` | SysML v2 官方文档要点摘录、功率/续航相关论文摘要 | 外部权威资料 | 十几份 |

**合计目标 30~50 份**（方案 7.2 的量级）。**都需要人工确认后才入库**，尤其：

- 官方文档与论文要点必须**标注出处（URL / 版本 / 取用日期）**，不得凭记忆转述；
- 项目数据表必须**标注是实测值还是设计值还是代理模型输出**——
  方案 10.2 的红线：**严禁把编造的数字当作实测结果**；
- 老师的样本模型同时承担「生成器样式基线」的职责，入库时请一并记录**版本与获取日期**。

## 检索与知识过滤（第三期，T14）

老师提出的要求里有「知识库 + 知识过滤」（方案 1.2 第 3 条）。规划：

- 检索只回带**最相关的片段**，不整篇塞进上下文（方案 10.3「上下文占用」风险的应对）；
- 过滤规则至少要能排除：过期的数值表、未标注来源的结论、与本项目机型无关的通用教程；
- 每份文档入库时记录**元信息头**（标题 / 来源 / 日期 / 数据类型 / 适用机型），供过滤使用。
