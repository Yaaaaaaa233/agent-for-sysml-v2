# IR Schema v1 字段说明

> 配套文件：`sysml-ir-v1.json`（机器可读的 JSON Schema，draft 2020-12）
> 配套文档：`渲染约定.md`（IR → SysML v2 文本的逐 kind 契约，含逆解析指引）
> 上位方案：《SysML 建模智能体技术方案》第 4 章（元模型子集 / 统一骨架 / MVP 元素清单 / 设计原则）
> 版本：`sysml-ir/v1`
> **v1 增补（2026-10-17）**：新增 `Constraint`、`Connection` 两种 kind，版本号不变、向后兼容；详见 §9。

**一句话**：这份文档说的是「LLM 到底要往外吐一张什么样的表」。
表的每一格都有类型、必填性和语义约束；填错了 `validate_model_json` 会带错误码告诉你错在哪一格。

---

## 1. 顶层结构

```json
{
  "schema": "sysml-ir/v1",
  "package": "CoaxialOctoRotor",
  "elements": [ /* 元素数组，至少 1 个 */ ],
  "meta": { "title": "...", "source": "...", "note": "..." }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schema` | string | **是** | 固定 `"sysml-ir/v1"`，不许自创版本号 |
| `package` | string | **是** | 顶层 package 名，同时也**充当 `owner` 的合法取值之一**（见 §3） |
| `elements` | array | **是** | 元素数组，至少 1 个，不许为空 |
| `meta` | object | 否 | 项目元信息（`title` / `source` / `note`），不参与渲染 |

**顶层不允许出现别的字段**（多写会报 `E-SCHEMA`）。

---

## 2. 两种「名字」：`id` 与 `name` 不是一回事

这是最容易混淆、也最影响正确性的一点，先讲清：

| | `id` | `name` |
| --- | --- | --- |
| 正则 | `^[A-Za-z_][A-Za-z0-9_-]*$` | `^[A-Za-z_][A-Za-z0-9_]*$` |
| **允许连字符** | ✅ 允许 | ❌ 不允许 |
| 作用域 | **全模型唯一** | **同 owner 下唯一** |
| 出现在哪 | JSON 里、追溯注释里 | 生成的 SysML v2 文本里当标识符 |
| 建议写法 | 带前缀的 kebab-case：`REQ-CRUISE-ENDURANCE`、`PART-BATTERY-PACK` | 英文大驼峰/小驼峰：`CruiseEndurance`、`batteryPack` |

**为什么分开**：方案 2.3 的示例里 `id` 就是 `REQ-CRUISE-ENDURANCE` 这种带连字符的形态，
一看就知道是哪一类元素、用来干什么；但连字符**不能**直接当 SysML v2 的标识符用，
所以落进文本的那个名字（`name`）必须严格。

`owner`、`relations[].target`、`PartUsage.typeRef`、`Constraint.parameters[]`、
`Connection.sourceRef/targetRef` 引用的都是 **`id`**，因此它们都允许连字符。

## 3. 统一元素骨架

每个元素都是下面这个形状（多写字段会报 `E-PROP-UNKNOWN` / `E-SCHEMA`）：

```json
{
  "id": "REQ-CRUISE-ENDURANCE",
  "kind": "Requirement",
  "name": "CruiseEndurance",
  "owner": "CoaxialOctoRotor",
  "properties": { /* 见 §4，不同 kind 不同 */ },
  "relations": [ /* 可选，见 §5 */ ]
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | string | **是** | 全模型唯一（`E-ID-DUP`）；本身要符合 id 正则（`E-ID-INVALID`） |
| `kind` | enum | **是** | 8 个受控值之一（`E-KIND-INVALID`） |
| `name` | string | **是** | 标识符正则（`E-NAME-INVALID`）；同 owner 唯一（`E-NAME-DUP`） |
| `owner` | string | **是** | **必须存在**：要么等于顶层 `package`，要么等于某个元素的 `id`（`E-OWNER-MISSING`） |
| `properties` | object | **是** | 必须是对象（`E-PROP-NOT-OBJECT`），子结构按 `kind` 定（§4） |
| `relations` | array | 否 | 每项 `type` / `target` / `rationale` 三个字段全必填（§5） |

**`owner` 的两种取值**（都合法）：

```jsonc
{ "id": "REQ-A", "owner": "CoaxialOctoRotor" }   // owner = package 名 → 渲染在 package 直下
{ "id": "PART-USE-BATTERY", "owner": "PART-POWER-CHAIN" }  // owner = 元素 id → 嵌套渲染在该元素体内
```

## 4. 八种 kind 的 `properties` 子结构

### 4.1 `PartDefinition` —— 结构定义（类型）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `description` | string | 否 | 人读说明 |
| `isAbstract` | boolean | 否 | 抽象定义，渲染为 `abstract part def X` |

```json
{ "id": "PART-BATTERY-PACK", "kind": "PartDefinition", "name": "BatteryPack",
  "owner": "CoaxialOctoRotor", "properties": { "description": "动力锂电池包。" } }
```

### 4.2 `PartUsage` —— 结构用法（具体那一份）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `typeRef` | string | **是** | **必须指向模型内某个 `kind == "PartDefinition"` 的元素 `id`** |
| `quantity` | number | 否 | 数量（默认 1）。**必须是数字** |
| `description` | string | 否 | 人读说明 |

```json
{ "id": "PART-USAGE-ESC", "kind": "PartUsage", "name": "escUnit",
  "owner": "PART-POWER-CHAIN",
  "properties": { "typeRef": "PART-ESC", "quantity": 8 } }
```

| 错误情形 | 错误码 |
| --- | --- |
| `typeRef` 缺失 | `E-PROP-REQUIRED` |
| `typeRef` 指向的 id 不存在 | `E-PARTUSAGE-TYPEREF-DANGLING` |
| `typeRef` 指向的元素不是 `PartDefinition` | `E-PARTUSAGE-TYPEREF-WRONGKIND` |
| `quantity` 写成字符串 | `E-PROP-TYPE` |

### 4.3 `Requirement` —— 需求

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | string | **是** | 需求原文，非空 |
| `acceptanceCriteria` | string | **是** | **可客观判定的验收判据**，非空。写不出来说明它还不是一条需求 |
| `verifyMethod` | enum | 否 | `analysis` / `inspection` / `test` / `simulation` / `demonstration` / `review` |
| `priority` | enum | 否 | `high` / `medium` / `low` |
| `rationale` | string | 否 | 为什么有这条需求 |
| `source` | string | 否 | 来源（任务书 / 会议纪要 / 标准条款） |
| `description` | string | 否 | 补充说明 |
| **其他任意标识符字段** | number / boolean / `{value, unit}` | 否 | **阈值与参数**，如 `minEnduranceHours: 4.0` |

**阈值字段的规则（方案 4.4 第 5 条）**：
除上面 7 个保留字段外，`properties` 里出现的任何字段都按「阈值/参数」处理，**只允许三种类型**：

```jsonc
"minEnduranceHours": 4.0                                  // ✅ 数字（推荐）
"isCritical": true                                        // ✅ 布尔
"minEnduranceHours": { "value": 4.0, "unit": "h" }        // ✅ 带单位对象（会加一条 warning）
"minEnduranceHours": "4 小时"                              // ❌ E-PROP-THRESHOLD-STRING
"minEnduranceHours": "4.0"                                // ❌ E-PROP-THRESHOLD-STRING
```

```json
{ "id": "REQ-CRUISE-ENDURANCE", "kind": "Requirement", "name": "CruiseEndurance",
  "owner": "CoaxialOctoRotor",
  "properties": {
    "text": "巡航时间不低于 4 小时",
    "acceptanceCriteria": "在巡航速度 v 与转速比 eta 的稳态工作点下，满电续航时间 T >= 4.0 h",
    "verifyMethod": "simulation",
    "priority": "high",
    "minEnduranceHours": 4.0
  },
  "relations": [
    { "type": "refines", "target": "REQ-MISSION-ENDURANCE", "rationale": "由任务级续航需求分解而来" },
    { "type": "satisfiedBy", "target": "PART-POWER-CHAIN", "rationale": "由功率链的设计参数保障" }
  ] }
```

### 4.4 `ActionDefinition` —— 功能 / 动作

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `inputs` | array | **是** | 可为空数组；每项 `{name(必填), typeRef?, unit?}` |
| `outputs` | array | **是** | 同上 |
| `description` | string | 否 | 人读说明 |

> ⚠️ **注意 `typeRef` 在这一层是「值类型名」**（如 `"Real"`），是个**自由字符串**，
> **不参与引用完整性检查**——这与 `PartUsage.typeRef`（元素引用）完全不同，别搞混。
> 端口 `name` 在同一个数组内不能重复。

```json
{ "id": "ACT-SIM-ENDURANCE", "kind": "ActionDefinition", "name": "EnduranceSimulationRun",
  "owner": "CoaxialOctoRotor",
  "properties": {
    "description": "续航仿真工况。",
    "inputs":  [ { "name": "cruiseSpeed", "typeRef": "Real", "unit": "m/s" },
                 { "name": "speedRatioEta", "typeRef": "Real" } ],
    "outputs": [ { "name": "enduranceHours", "typeRef": "Real", "unit": "h" } ]
  },
  "relations": [ { "type": "verifies", "target": "REQ-CRUISE-ENDURANCE", "rationale": "直接验证续航指标" } ] }
```

### 4.5 `StateDefinition` —— 状态机

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `states` | array of identifier | **是** | 非空、不重复 |
| `initial` | identifier | 否 | 初态，**必须在 `states` 里** |
| `transitions` | array | 否 | 每项 `{from(必填), to(必填), trigger?, guard?}` |
| `description` | string | 否 | 人读说明 |

`transitions` 的 `from` / `to` **都必须出现在 `states` 里**（`E-STATE-TRANSITION-ENDPOINT`）。

```json
{ "id": "STATE-FLIGHT-MODE", "kind": "StateDefinition", "name": "FlightModeStates",
  "owner": "CoaxialOctoRotor",
  "properties": {
    "states": ["Grounded", "Climbing", "Cruising", "Returning", "Landing"],
    "initial": "Grounded",
    "transitions": [
      { "from": "Grounded",  "to": "Climbing",  "trigger": "takeoff command" },
      { "from": "Climbing",  "to": "Cruising",  "trigger": "altitude reached" },
      { "from": "Cruising",  "to": "Returning", "trigger": "reserve energy reached" }
    ]
  } }
```

### 4.6 `Attribute` —— 数值属性（参数）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `valueType` | enum | **是** | `Real` / `Integer` / `Boolean` / `String` |
| `defaultValue` | number / integer / boolean / string | 否 | **类型必须与 `valueType` 匹配**（`E-ATTR-DEFAULT-TYPE`） |
| `unit` | string | 否 | **单位单独成字段，非空**——不许写进数值字符串 |
| `description` | string | 否 | 人读说明；**公式请写进正式的 `Constraint` 元素**（见 §4.7），不要只写在描述里 |

```json
{ "id": "ATTR-BATTERY-CAPACITY", "kind": "Attribute", "name": "batteryCapacityWh",
  "owner": "PART-BATTERY-PACK",
  "properties": { "valueType": "Real", "defaultValue": 1200.0, "unit": "Wh",
                  "description": "电池包标称容量 E_batt。" } }
```

> 单位现在渲染为后缀 `[<unit>]`，不再写成行内注释；IR 的 `Wh` 会渲染成 `W*h`
> （官方标准库没有 `Wh`，别名规则见 `渲染约定.md` §2.6），逆解析再还原回 `Wh`。

### 4.7 `Constraint` —— 参数约束 / 公式（v1 增补）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `expression` | string | **是** | 单行公式文本，非空，**禁止换行**（`E-CONSTRAINT-NO-EXPRESSION` / `E-CONSTRAINT-EXPR-MULTILINE`） |
| `parameters` | array of id | **是** | 至少 1 项；每项必须引用模型内 `kind == "Attribute"` 的元素 `id`（`E-CONSTRAINT-PARAMS-INVALID` / `E-CONSTRAINT-PARAM-DANGLING` / `E-CONSTRAINT-PARAM-WRONGKIND`） |
| `description` | string | 否 | 人读说明 |

```json
{ "id": "CONSTRAINT-ENDURANCE-BUDGET", "kind": "Constraint", "name": "EnduranceBudget",
  "owner": "PART-POWER-CHAIN",
  "properties": {
    "expression": "T = batteryCapacityWh * usableEnergyFraction / cruisePowerW",
    "parameters": ["ATTR-BATTERY-CAPACITY", "ATTR-USABLE-FRACTION", "ATTR-CRUISE-POWER", "ATTR-ENDURANCE"],
    "description": "续航换算约束；参数绑定到已有 Attribute。"
  } }
```

| 错误情形 | 错误码 |
| --- | --- |
| 缺 `expression` 或为空白 | `E-CONSTRAINT-NO-EXPRESSION` |
| `expression` 含换行 | `E-CONSTRAINT-EXPR-MULTILINE` |
| 缺 `parameters`、空数组、某项不是 id 字符串 | `E-CONSTRAINT-PARAMS-INVALID` |
| 参数指向的 id 不存在 | `E-CONSTRAINT-PARAM-DANGLING` |
| 参数指向的元素不是 `Attribute` | `E-CONSTRAINT-PARAM-WRONGKIND` |

> 公式本身是**自由文本**：不解析、不计算、不做量纲检查。它表达「这条约束写了什么」，
> 不保证与参数数值在数学上一致。

### 4.8 `Connection` —— 两个 PartUsage 之间的连接（v1 增补）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sourceRef` | string | **是** | 连接起点，必须引用模型内 `kind == "PartUsage"` 的元素 `id` |
| `targetRef` | string | **是** | 连接终点，必须引用 `PartUsage`，且**不能与 `sourceRef` 相同** |
| `flowKind` | enum | **是** | `electrical` / `mechanical` / `data` / `thermal` / `fluid` / `generic` |
| `description` | string | 否 | 人读说明 |

语义约束：

- 两端的 kind 必须是 `PartUsage`（`E-CONNECTION-ENDPOINT-WRONGKIND`），id 必须存在
  （`E-CONNECTION-ENDPOINT-DANGLING`）；
- 两端的 `owner` 必须**等于 `Connection` 自身的 `owner`**
  （`E-CONNECTION-OWNER-MISMATCH`）——连接与被连接者必须在同一个结构层级；
- `sourceRef != targetRef`（`E-CONNECTION-SELF`）；
- `(sourceRef, targetRef, flowKind)` 三元组全模型唯一（`E-CONNECTION-DUP`）；
- 同 owner 下 `name` 唯一规则照旧（`E-NAME-DUP`）。

```json
{ "id": "CONN-BATTERY-ESC", "kind": "Connection", "name": "batteryToEsc",
  "owner": "PART-POWER-CHAIN",
  "properties": {
    "sourceRef": "PART-USAGE-BATTERY",
    "targetRef": "PART-USAGE-ESC",
    "flowKind": "electrical",
    "description": "电池直流母线馈入八路电调。"
  } }
```

| 错误情形 | 错误码 |
| --- | --- |
| 缺 `sourceRef` / `targetRef` / `flowKind` | `E-PROP-REQUIRED` |
| 端点 id 不存在 | `E-CONNECTION-ENDPOINT-DANGLING` |
| 端点不是 `PartUsage` | `E-CONNECTION-ENDPOINT-WRONGKIND` |
| 端点与 Connection 不同 owner | `E-CONNECTION-OWNER-MISMATCH` |
| 两端相同 | `E-CONNECTION-SELF` |
| 三元组重复 | `E-CONNECTION-DUP` |
| `flowKind` 不在受控枚举内 | `E-ENUM-INVALID` |

> **`Connection` vs `relations[].type = "connects"`**：前者是正式元素（有 id、flowKind、
> 两端引用），后者是一行追溯注释。两者可以并存，但不要用 `connects` 关系替代 `Connection`，
> 也不要反过来。渲染形态见 `渲染约定.md` §2.8。

## 5. `relations` —— 关系

每项**三个字段全必填**（少一个报 `E-REL-FIELD-MISSING`）：

```json
{ "type": "refines", "target": "REQ-MISSION-ENDURANCE", "rationale": "由任务级续航需求分解而来" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | enum | **是** | 5 个受控值之一（`E-REL-TYPE-INVALID`） |
| `target` | string | **是** | **必须指向模型内已存在的元素 `id`**（`E-REL-TARGET-DANGLING`） |
| `rationale` | string | **是** | 非空（`E-REL-NO-RATIONALE`）。**没理由的追溯关系等于没建立** |

### 五种 `type` 的方向语义

| `type` | 读作 | 常见用法 |
| --- | --- | --- |
| `refines` | **A 细化 B**（A 是更细的那条） | 巡航续航 `refines` 任务级续航 |
| `satisfiedBy` | **A 被 B 满足** | 需求 `satisfiedBy` 结构或功能 |
| `decomposes` | **A 分解为 B** | 整机 `decomposes` 功率链；上层功能 `decomposes` 下层功能 |
| `verifies` | **A 验证 B** | 仿真工况 `verifies` 需求（MVP 没有专门的「验证用例」kind，用 `ActionDefinition` 充当） |
| `connects` | **A 连接到 B** | 电池用法 `connects` 电调用法（功率链） |

> **`verifies` 的方向提醒**：是「验证方 → 被验证的需求」。把方向写反了校验不会报错，
> 但 `W-REQ-NO-VERIFY` 的检查是**双向扫描**的，所以不会误报；真正的风险是追溯矩阵读起来别扭。

### `relations` 是可选的

不写 `relations` 字段、或写成空数组 `[]`，都合法。但会触发相应的 warning：

- 需求没有 `satisfiedBy` → `W-REQ-NO-SATISFY`
- 需求标了 `verifyMethod` 却没有任何 `verifies`（双向）→ `W-REQ-NO-VERIFY`
- PartDefinition 既没被引用、自己也没关系 → `W-ELEMENT-ORPHAN`
- PartDefinition 没被任何 `PartUsage.typeRef` 用到 → `W-PARTDEF-UNUSED`

## 6. 校验产物：错误码全表

`validate_model_json` 返回 `{ "ok": bool, "errors": [...], "warnings": [...], "schemaLayer": "..." }`，
每条含 `code` / `element` / `message`（另附 `pointer` 方便机器定位）。

> 本章 §6.1–§6.3 是**校验器**的错误码/警告码；§6.4–§6.8 是二期工具
> （`patch_model` / `traceability` / `parse_sysml` / `query_model` / `export_simulink` /
> `verify_sysml(official=true)`）的返回结构与错误码。返回结构一律以实现为准。

### 6.1 errors（`ok=false`，必须清零才能生成）

| 错误码 | 触发条件 |
| --- | --- |
| `E-INPUT-NOT-JSON` | 输入是字符串但不是合法 JSON |
| `E-ROOT-NOT-OBJECT` | 顶层不是对象 |
| `E-SCHEMA-VERSION` | `schema` 不是 `sysml-ir/v1` |
| `E-PACKAGE-INVALID` | `package` 不是合法标识符 |
| `E-ELEMENTS-NOT-ARRAY` / `E-ELEMENTS-EMPTY` | `elements` 不是数组 / 是空数组 |
| `E-ELEMENT-NOT-OBJECT` | 数组里某项不是对象 |
| `E-FIELD-MISSING` | 缺 `id`/`kind`/`name`/`owner`/`properties`（或顶层 `schema`/`package`/`elements`） |
| `E-ID-INVALID` / `E-ID-DUP` | `id` 不合规 / 重复 |
| `E-KIND-INVALID` | `kind` 不在 8 个受控值内 |
| `E-NAME-INVALID` / `E-NAME-DUP` | `name` 不合规 / 同 owner 下重名 |
| `E-OWNER-INVALID` / `E-OWNER-MISSING` | `owner` 不合规 / 在模型内不存在 |
| `E-PROP-NOT-OBJECT` | `properties` 不是对象 |
| `E-PROP-REQUIRED` | 缺该 kind 的必填子字段（`typeRef`/`inputs`/`outputs`/`states`/`valueType`/`sourceRef`/`targetRef`/`flowKind`） |
| `E-PROP-UNKNOWN` | 该 kind 不允许这个子字段（`Requirement` 的阈值字段除外） |
| `E-PROP-TYPE` | 子字段类型不对（含 `quantity` 写成字符串） |
| `E-REQ-NO-TEXT` / `E-REQ-NO-ACCEPTANCE` | 需求缺 / 空白的正文与验收判据 |
| `E-PROP-THRESHOLD-STRING` | **需求阈值写成了字符串** |
| `E-PARTUSAGE-TYPEREF-DANGLING` | `typeRef` 悬空 |
| `E-PARTUSAGE-TYPEREF-WRONGKIND` | `typeRef` 没指向 `PartDefinition` |
| `E-ENUM-INVALID` | `verifyMethod` / `priority` / `valueType` 不在受控枚举内 |
| `E-ATTR-DEFAULT-TYPE` | `defaultValue` 与 `valueType` 不匹配 |
| `E-STATE-STATES-INVALID` / `E-STATE-DUP` | `states` 不是非空数组 / 状态名重复 |
| `E-STATE-INITIAL-NOTFOUND` | `initial` 不在 `states` 里 |
| `E-STATE-TRANSITIONS-INVALID` | `transitions` 不是数组或某项不是对象 |
| `E-STATE-TRANSITION-ENDPOINT` | transition 的 `from`/`to` 不在 `states` 里 |
| `E-CONSTRAINT-NO-EXPRESSION` | `Constraint.expression` 缺失或空白 |
| `E-CONSTRAINT-EXPR-MULTILINE` | `Constraint.expression` 含换行 |
| `E-CONSTRAINT-PARAMS-INVALID` | `parameters` 缺失 / 空数组 / 某项不是 id 字符串 |
| `E-CONSTRAINT-PARAM-DANGLING` | 参数指向的 id 不存在 |
| `E-CONSTRAINT-PARAM-WRONGKIND` | 参数指向的元素不是 `Attribute` |
| `E-CONNECTION-ENDPOINT-DANGLING` | `sourceRef` / `targetRef` 指向的 id 不存在 |
| `E-CONNECTION-ENDPOINT-WRONGKIND` | 端点指向的元素不是 `PartUsage` |
| `E-CONNECTION-OWNER-MISMATCH` | 端点 owner 与 Connection 的 owner 不一致 |
| `E-CONNECTION-SELF` | `sourceRef == targetRef` |
| `E-CONNECTION-DUP` | `(sourceRef, targetRef, flowKind)` 三元组重复 |
| `E-REL-NOT-ARRAY` / `E-REL-ITEM-NOT-OBJECT` | `relations` 不是数组 / 某项不是对象 |
| `E-REL-FIELD-MISSING` | 关系项缺 `type`/`target`/`rationale` |
| `E-REL-NO-RATIONALE` | `rationale` 为空 |
| `E-REL-TYPE-INVALID` | `type` 不在 5 个受控值内 |
| `E-REL-TARGET-INVALID` / `E-REL-TARGET-DANGLING` | `target` 不合规 / 悬空 |
| `E-SCHEMA` | 第二层 JSON Schema 交叉检查发现的形状问题（装了 `jsonschema` 才会出现） |

### 6.3 `schemaLayer` 字段

如实说明第二层跑没跑：`unavailable`（没装 `jsonschema`）/ `skipped` / `unreadable` / `invalid` /

> 只是少了这一层交叉检查。

### 6.4 `patch_model`：返回、`diff` 与 `cascade` 语义（二期 T8）

返回**恒为** `{"ok", "model", "diff", "errors", "warnings"}`。
`ok=false` 时 `model` **一定为 `null`**（不回传半应用结果），`diff` 里已执行的步骤会标注
「已回滚，未生效」。纯函数：不修改传入的 `model`，所有操作都在深拷贝上完成。

| `op` | 必填字段 | 语义 |
| --- | --- | --- |
| `add_element` | `element` | 新增元素；`element.id` 不得与现有 id 重复 |
| `update_element` | `id` + `element`（完整元素） | 整体替换；`element.id` 必须等于 `id` |
| `remove_element` | `id`；可选 `cascade`（默认 `false`） | 默认拒绝删除仍被引用的元素；`cascade=true` 时级联清理 |
| `add_relation` | `id` + `relation`（`{type,target,rationale}`） | 往宿主元素的 `relations` 追加一条 |
| `remove_relation` | `id` + `type` + `target` | 精确删除宿主元素上第一条同型同目标的关系 |

`diff` 每条为 `{"change": "+|-|~", "kind": "element|relation", "id", "detail"}`；
`kind="relation"` 时 `id` 取**宿主元素**的 id，`detail` 写明 `type → target`。

**「引用」的口径**（与 `query_model(referrers_of=...)` 一致，并**额外**算上 `owner`）：
`relations[].target`、`properties.typeRef`、`owner`。

**`cascade=true` 的清理规则**（逐条写进 `diff`）：

- 指向被删元素的 `relations` 项 → **摘除**（关系可以不存在，元素仍然合法）；
- `properties.typeRef` 指向被删元素的元素 → **整个元素一并删除**（`typeRef` 是 `PartUsage`
  的必填字段，摘掉引用会变非法模型）；
- `owner` 指向被删元素的子元素 → **整棵子树一并删除**（父元素没了，子元素无处挂靠）。

| 错误码 | 触发条件 |
| --- | --- |
| `E-PATCH-MODEL-INVALID` | `model` 不是对象 / 不是合法 JSON / `elements` 不是数组 |
| `E-PATCH-OPS-NOT-ARRAY` | `ops` 不是数组 |
| `E-PATCH-OP-INVALID` | `ops[i]` 不是对象 |
| `E-PATCH-UNKNOWN-OP` | `op` 不在上表 5 类之内 |
| `E-PATCH-ID-MISSING` | op 缺少合法 `id`（或 `element.id`） |
| `E-PATCH-ID-NOTFOUND` | `update_element` / `remove_element` 的 `id` 在模型内不存在 |
| `E-PATCH-ID-DUP` | `add_element` 的 id 已被占用 |
| `E-PATCH-ID-MISMATCH` | `update_element.element.id` 与 `id` 不一致 |
| `E-PATCH-ELEMENT-INVALID` | `element` 不是对象 |
| `E-REF-DEPENDENT` | `remove_element` 默认模式下元素仍被引用（逐条列出引用方） |
| `E-PATCH-REL-INVALID` | `relation` 不是对象 / 缺 `type` 或 `target` |
| `E-PATCH-REL-NOT-ARRAY` | 宿主元素的 `relations` 不是数组 |
| `E-PATCH-REL-DUP` | `add_relation` 的 type+target 已存在 |
| `E-PATCH-REL-NOTFOUND` | `remove_relation` 找不到匹配项 |
| `E-PATCH-VALIDATE-FAILED` | 补丁后 `validate_model_json` 仍报错（其后各条为底层原始错误） |

### 6.5 `traceability`：返回字段与错误码（二期 T9）

返回 `{"ok", "matrix", "gaps", "impact", "content", "errors"}`。

| 字段 | 内容 |
| --- | --- |
| `matrix` | 每条 `Requirement` 一行：`requirement`（id）、`name`、`text_short`（`properties.text` 前 60 字）、`satisfiedBy`（id 列表）、`verifiedBy`（id 列表）、`status` |
| `gaps` | `unsatisfied`（没有 satisfiedBy）、`unverified_requirement`（没有 verifies）、`unverified_action`（没有任何 `verifies` 关系的 `ActionDefinition`） |
| `impact` | 给出 `focus` 时才有：`id`、`direct`（直接引用方）、`transitive`（传递引用方）、`affected_requirements`（影响面里的需求 id） |
| `content` | `fmt="md"` 时是渲染好的 Markdown；`fmt="json"` 时为 `null` |

`status` 四态：`satisfied-and-verified` / `satisfied` / `verified-only` / `unsatisfied`。

**引用边**（反向 BFS 用，与 `query_model` 的口径**不同**）：`relations[].target`、
`properties.typeRef`、**`owner`（父→子）**——影响面要能顺带把子树算进去。

| 错误码 | 触发条件 |
| --- | --- |
| `E-TRACE-MODEL-INVALID` | `model.elements` 不是数组 |
| `E-TRACE-FMT-INVALID` | `fmt` 不是 `json` / `md` |
| `E-TRACE-FOCUS-INVALID` | `focus` 不是字符串或字符串数组（含空字符串 / 空数组） |
| `E-TRACE-FOCUS-NOTFOUND` | `focus` 里的 id 在模型内不存在（逐条列出） |

> 诚实口径：`content` 只把 IR 里**已经写了**的关系排版出来，不做语义推断；
> 需求是否真的被满足、动作是否真的能验证需求，仍需人判断。

### 6.6 `parse_sysml`：子集边界与 `unsupported`（二期 T8）

返回 `{"ok", "model", "warnings", "unsupported", "errors", "stats"}`。`ok` 仅在
**没有任何 error、也没有任何 unsupported** 时为 `true`。

- **只解析渲染子集**：8 种 kind、`[unit]` / `[n]` 后缀、状态机（`entry; then` / `transition`）、
  `Constraint` / `Connection` 的结构化注释、`// id:` / `// description:` / 追溯关系注释、
  `private import ScalarValues::*;` / `private import SI::*;` 两行标准库 import。
  **不是**完整 SysML v2 解析器。
- **子集外构造**（`item` / `port` / `satisfy` / 裸 `import` / 多行块注释 / 第二个顶层
  `package` 等）不崩溃、不静默丢弃：逐条进 `unsupported`，每项 `{line, snippet, reason}`，
  并令 `ok=false`。
- 名字→id 还原口径：**同 owner 优先，其次全局唯一**；仍歧义 → `E-PARSE-AMBIGUOUS`，
  找不到 → `E-PARSE-UNRESOLVED`，不猜测。
- 解析结果**仍须**过 `validate_model_json`：`parse_sysml` 不代替校验。

| 错误码 | 触发条件 |
| --- | --- |
| `E-PARSE-INPUT` | 输入不是文本 |
| `E-PARSE-NO-PACKAGE` | 找不到顶层 `package` 声明 |
| `E-PARSE-UNBALANCED` / `E-PARSE-UNCLOSED` | 花括号不配对 / 块或注释未闭合 |
| `E-PARSE-BAD-ID` | `// id:` 里的 id 不合规 |
| `E-PARSE-DUPLICATE-ID` / `E-PARSE-DUPLICATE-NAME` | 解析出的 id / 同 owner 下 name 重复 |
| `E-PARSE-LITERAL` | 字面量无法解析（数字/布尔/字符串） |
| `E-PARSE-ATTRIBUTE` | `attribute` 行形态不符合子集 |
| `E-PARSE-QUANTITY` | `[n]` 多重度无法解析 |
| `E-PARSE-REQ-FIELD` | `requirement def` 体内的字段无法归位 |
| `E-PARSE-RELATION-SOURCE` | 追溯注释的源 id 无法确定 |
| `E-PARSE-CONN-ANNOTATION` / `E-PARSE-CONN-NO-CONNECT` / `E-PARSE-CONNECT` | `Connection` 标注行格式错 / 注释后没有 `connect` 语句 / `connect` 语句无法解析 |
| `E-PARSE-AMBIGUOUS` / `E-PARSE-UNRESOLVED` | 名字→id 有多个候选 / 找不到候选 |
| `E-PARSE-INTERNAL` | 解析器内部异常（保底，不吞栈） |

### 6.7 `query_model`：`model` | `path` 二选一与 `SYSML_QUERY_ROOT`（二期 T9）

返回 `{"ok", "mode", "count", "results", ...}`，`mode` ∈ `search` / `referrers` /
`duplicates` / `unsatisfied` / `error`。错误不走 `errors` 数组，而是
`{"ok": false, "mode": "error", "count": 0, "results": [], "error": "<原因>"}`——
错误码写在 `error` 文本里。

- **`model` 与 `path` 只能二选一**：直接给 IR JSON，或给服务端本地 IR JSON 文件路径。
  同时给 → 报「只能二选一」；都不给 → 报「缺少输入」。`path` 仅服务端本机可用，
  云端 / streamable-http 部署应上传内容而非路径。
- **`SYSML_QUERY_ROOT`**：设置后 `path`（**解析符号链接之后**）必须落在该根目录之下
  （含根本身），否则报 `E-QUERY-PATH-OUTSIDE-ROOT`；变量本身不是合法目录则报
  `E-QUERY-PATH-ROOT-INVALID`。**不设置时不限制**（本地开发行为不变）。
  streamable-http 启动时若未设置，服务会把工作目录设为默认根并在启动输出里提示一句。
- **引用边口径**（`referrers_of` 用）：`relations[].target`、`properties.typeRef`、
  `Constraint.properties.parameters`（元素 id 数组）、
  `Connection.properties.sourceRef` / `targetRef`。**`owner` 归属链不算引用边**。

| 错误码 | 触发条件 |
| --- | --- |
| `E-QUERY-PATH-OUTSIDE-ROOT` | `path` 解析后落在 `SYSML_QUERY_ROOT` 之外（或用软链接绕过） |
| `E-QUERY-PATH-ROOT-INVALID` | `SYSML_QUERY_ROOT` 本身无法解析为目录 |

### 6.8 `export_simulink` 与 `verify_sysml(official=true)`

`export_simulink` 返回 `{"ok", "content", "rows", "notes", "errors"}`，错误项形如
`{code, element, message}`：

| 错误码 | 触发条件 |
| --- | --- |
| `E-EXPORT-INPUT` | `model` 不是对象 / 不是合法 JSON |
| `E-EXPORT-FMT` | `fmt` 不是 `csv` / `json` / `md` |
| `E-EXPORT-SCOPE` | `scope` 不是 `all` / `attributes` / `constraints` / `requirements` |

`verify_sysml(official=true)` 追加 `official` 键：
`{ok, backend, status, diagnostics, detail}`，`status` ∈ `available` / `unavailable` /
`unverified`。**失败关闭**：只要后端不可用、未确认、或有诊断，顶层 `ok` 一律为 `false`——
没拿到可信的官方结论就不说通过。

## 7. 渲染：IR 的每个字段落到文本的哪里

`generate_sysml` 的映射（详见 `mcp-server/tools/generator.py`）：

| IR | 生成的 SysML v2 |
| --- | --- |
| `package` | `package <package> { ... }`；package 内固定两行 `private import ScalarValues::*;` / `private import SI::*;` |
| 所有元素 `id` | 声明前一行 `// id: <id>`（`Connection` 写在结构化注释里） |
| `PartDefinition` | `part def <name> { ... }`（`isAbstract` → `abstract part def`） |
| `PartUsage` | `part <name> : <typeRef 的 name>[n];`；`quantity` 存在就加 `[n]`（含 1），不存在不加 |
| `Requirement` | `requirement def <name> { doc /* text */ doc /* 验收判据: ... */ attribute ... }` |
| `ActionDefinition` | `action def <name> { in <name> : <typeRef>; out ...; }`（端口 unit 仍为 `// unit:` 注释） |
| `StateDefinition` | `state def <name> { entry; then X; state X; ... transition <合成名> first A [if (...)] then B; }`（trigger 为上一行 `// trigger:` 注释） |
| `Attribute` | `attribute <name> : <valueType> = <defaultValue> [<unit>];`（无 unit 则无后缀） |
| `Constraint` | `constraint def <name> { // expression: ... // parameters: a, b }` |
| `Connection` | `// Connection <id> flowKind=<flowKind> name=<name>` + `connect <src> to <tgt>;` |
| 元素的 `description` | 声明前一行 `// description: ...` |
| `relations` | 元素体内 `// 追溯关系 (relations):` + 每行 `// <srcId> --<type>--> <targetId>  (rationale)` |
| `owner` 是元素 | 该元素**嵌套渲染**在 owner 体内（按 kind 再按 id 排序） |

**逐 kind 的完整契约、结构化注释格式与逆解析正则**见 `渲染约定.md`。
2026-10-17 实测口径（范围限定）：在补齐标准库 import 头与 `Wh` → `W*h` 别名后，
golden / base / extended 三份生成文本经官方 Pilot Implementation（release 2026-08）
解析均为 **0 条诊断**（证据：`docs/probe-official-parser/EVIDENCE.txt` §13）。
这只说明**语法与引用解析**被官方实现接受；**语义/建模质量未验证**，
不得写成「已通过官方解析器验证」。内置 lint + 元素级比对也不等同于官方解析器。
此外，标杆案例的 `1200 Wh` / `240 W` / `0.95` / `0.85` / `0.72`
等数值是**占位示例值**，不得作为实测结论。

## 8. 一个可以直接抄的最小完整模型

```json
{
  "schema": "sysml-ir/v1",
  "package": "Demo",
  "elements": [
    { "id": "PART-DEF-MOTOR", "kind": "PartDefinition", "name": "Motor",
      "owner": "Demo", "properties": { "description": "无刷电机。" } },
    { "id": "PART-USE-MOTOR", "kind": "PartUsage", "name": "motorOne",
      "owner": "Demo", "properties": { "typeRef": "PART-DEF-MOTOR", "quantity": 4 } },
    { "id": "REQ-SPEED", "kind": "Requirement", "name": "SpeedRequirement",
      "owner": "Demo",
      "properties": {
        "text": "稳态转速不低于 1000 rpm",
        "acceptanceCriteria": "稳态转速 n >= 1000 rpm",
        "verifyMethod": "simulation",
        "minSpeedRpm": 1000.0
      },
      "relations": [
        { "type": "satisfiedBy", "target": "PART-USE-MOTOR", "rationale": "由电机选型满足" }
      ] }
  ]
}
```

存成 `demo.ir.json` 后：

```bash
cd sysml-modeling-agent/mcp-server
python run_server.py --call validate_model_json --input ../demo.ir.json   # ok: true
python run_server.py --call generate_sysml       --input ../demo.ir.json   # 打印 SysML v2 文本
```

## 9. v1 增补记录（2026-10-17）

本次在 **`schema: "sysml-ir/v1"` 内向后兼容地**增补两种 kind，**不改版本号**：

| 增补项 | 内容 |
| --- | --- |
| 新 kind `Constraint` | `expression`（单行公式文本，非空、禁止换行）+ `parameters`（≥1 个元素 id，必须引用 `Attribute`）+ 可选 `description`。对应方案 4.3 第 7 行。 |
| 新 kind `Connection` | `sourceRef` / `targetRef`（必须引用同 owner 的 `PartUsage`，且两端不同）+ `flowKind`（6 值受控枚举）+ 可选 `description`。对应方案 4.3 第 8 行。 |
| 新错误码 | `E-CONSTRAINT-*`、`E-CONNECTION-*`（全表见 §6.1） |
| 渲染语法升级 | `Attribute.unit` → `[unit]` 后缀；`PartUsage.quantity` → `[n]` 后缀；`StateDefinition.transitions` → 官方记法 `transition <name> first ... [if (...)] then ...;`、初始态 `entry; then X;`，trigger 以 `// trigger:` 结构化注释承载（详见 `渲染约定.md`） |
| 回验适配 | `sysml_lint` 能抽取 `constraint def`、`// expression:` / `// parameters:`、`// Connection ...` + `connect`，并对上面三种新语法做结构自查；`roundtrip_check` 对 Constraint/Connection 做字段级比对 |

**向后兼容性**：旧模型（不含新 kind、仍用旧注释形态）在语义上不受影响；但**生成文本会变化**
（单位/数量/状态迁移/阈值单位改用新语法），因此旧产物必须用 `generate_sysml` 重新生成，
不要手改历史 `.sysml` 文件。

**回验边界（2026-10-17）**：新渲染语法 + 标准库 import 头 + `Wh` → `W*h` 别名后的生成文本，
经官方 Pilot Implementation 实测为 0 条诊断；该结论仅覆盖语法与引用解析，语义/建模质量未验证。
详见 `渲染约定.md` §0 与 `docs/probe-official-parser/EVIDENCE.txt` §13。
另：`parse_sysml` 提供文本 → IR 的逆解析，但只支持本工具链渲染子集（子集外进 `unsupported`）。
