# IR Schema v1 字段说明

> 配套文件：`sysml-ir-v1.json`（机器可读的 JSON Schema，draft 2020-12）
> 上位方案：《SysML 建模智能体技术方案》第 4 章（元模型子集 / 统一骨架 / MVP 元素清单 / 设计原则）
> 版本：`sysml-ir/v1`

**一句话**：这份文档说的是「LLM 到底要往外吐一张什么样的表」。
表的每一格都有类型、必填性和语义约束；填错了 `validate_model_json` 会带错误码告诉你错在哪一格。

---

## 1. 顶层结构

```json
{
  "schema": "sysml-ir/v1",
  "package": "CoaxialOctoRotor",
  "elements": [ /* 元素数组，至少 1 个 */ ],
  "meta": { "title": "...", "source": "...", "note": "..." }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schema` | string | **是** | 固定 `"sysml-ir/v1"`，不许自创版本号 |
| `package` | string | **是** | 顶层 package 名，同时也**充当 `owner` 的合法取值之一**（见 §3） |
| `elements` | array | **是** | 元素数组，至少 1 个，不许为空 |
| `meta` | object | 否 | 项目元信息（`title` / `source` / `note`），不参与渲染 |

**顶层不允许出现别的字段**（多写会报 `E-SCHEMA`）。

---

## 2. 两种「名字」：`id` 与 `name` 不是一回事

这是最容易混淆、也最影响正确性的一点，先讲清：

| | `id` | `name` |
| --- | --- | --- |
| 正则 | `^[A-Za-z_][A-Za-z0-9_-]*$` | `^[A-Za-z_][A-Za-z0-9_]*$` |
| **允许连字符** | ✅ 允许 | ❌ 不允许 |
| 作用域 | **全模型唯一** | **同 owner 下唯一** |
| 出现在哪 | JSON 里、追溯注释里 | 生成的 SysML v2 文本里当标识符 |
| 建议写法 | 带前缀的 kebab-case：`REQ-CRUISE-ENDURANCE`、`PART-BATTERY-PACK` | 英文大驼峰/小驼峰：`CruiseEndurance`、`batteryPack` |

**为什么分开**：方案 2.3 的示例里 `id` 就是 `REQ-CRUISE-ENDURANCE` 这种带连字符的形态，
一看就知道是哪一类元素、用来干什么；但连字符**不能**直接当 SysML v2 的标识符用，
所以落进文本的那个名字（`name`）必须严格。

`owner`、`relations[].target`、`PartUsage.typeRef` 引用的都是 **`id`**，因此它们都允许连字符。

## 3. 统一元素骨架

每个元素都是下面这个形状（多写字段会报 `E-PROP-UNKNOWN` / `E-SCHEMA`）：

```json
{
  "id": "REQ-CRUISE-ENDURANCE",
  "kind": "Requirement",
  "name": "CruiseEndurance",
  "owner": "CoaxialOctoRotor",
  "properties": { /* 见 §4，不同 kind 不同 */ },
  "relations": [ /* 可选，见 §5 */ ]
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | string | **是** | 全模型唯一（`E-ID-DUP`）；本身要符合 id 正则（`E-ID-INVALID`） |
| `kind` | enum | **是** | 6 个受控值之一（`E-KIND-INVALID`） |
| `name` | string | **是** | 标识符正则（`E-NAME-INVALID`）；同 owner 唯一（`E-NAME-DUP`） |
| `owner` | string | **是** | **必须存在**：要么等于顶层 `package`，要么等于某个元素的 `id`（`E-OWNER-MISSING`） |
| `properties` | object | **是** | 必须是对象（`E-PROP-NOT-OBJECT`），子结构按 `kind` 定（§4） |
| `relations` | array | 否 | 每项 `type` / `target` / `rationale` 三个字段全必填（§5） |

**`owner` 的两种取值**（都合法）：

```jsonc
{ "id": "REQ-A", "owner": "CoaxialOctoRotor" }   // owner = package 名 → 渲染在 package 直下
{ "id": "PART-USE-BATTERY", "owner": "PART-POWER-CHAIN" }  // owner = 元素 id → 嵌套渲染在该元素体内
```

## 4. 六种 kind 的 `properties` 子结构

### 4.1 `PartDefinition` —— 结构定义（类型）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `description` | string | 否 | 人读说明 |
| `isAbstract` | boolean | 否 | 抽象定义，渲染为 `abstract part def X` |

```json
{ "id": "PART-BATTERY-PACK", "kind": "PartDefinition", "name": "BatteryPack",
  "owner": "CoaxialOctoRotor", "properties": { "description": "动力锂电池包。" } }
```

### 4.2 `PartUsage` —— 结构用法（具体那一份）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `typeRef` | string | **是** | **必须指向模型内某个 `kind == "PartDefinition"` 的元素 `id`** |
| `quantity` | number | 否 | 数量（默认 1）。**必须是数字** |
| `description` | string | 否 | 人读说明 |

```json
{ "id": "PART-USAGE-ESC", "kind": "PartUsage", "name": "escUnit",
  "owner": "PART-POWER-CHAIN",
  "properties": { "typeRef": "PART-ESC", "quantity": 8 } }
```

| 错误情形 | 错误码 |
| --- | --- |
| `typeRef` 缺失 | `E-PROP-REQUIRED` |
| `typeRef` 指向的 id 不存在 | `E-PARTUSAGE-TYPEREF-DANGLING` |
| `typeRef` 指向的元素不是 `PartDefinition` | `E-PARTUSAGE-TYPEREF-WRONGKIND` |
| `quantity` 写成字符串 | `E-PROP-TYPE` |

### 4.3 `Requirement` —— 需求

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | string | **是** | 需求原文，非空 |
| `acceptanceCriteria` | string | **是** | **可客观判定的验收判据**，非空。写不出来说明它还不是一条需求 |
| `verifyMethod` | enum | 否 | `analysis` / `inspection` / `test` / `simulation` / `demonstration` / `review` |
| `priority` | enum | 否 | `high` / `medium` / `low` |
| `rationale` | string | 否 | 为什么有这条需求 |
| `source` | string | 否 | 来源（任务书 / 会议纪要 / 标准条款） |
| `description` | string | 否 | 补充说明 |
| **其他任意标识符字段** | number / boolean / `{value, unit}` | 否 | **阈值与参数**，如 `minEnduranceHours: 4.0` |

**阈值字段的规则（方案 4.4 第 5 条）**：
除上面 7 个保留字段外，`properties` 里出现的任何字段都按「阈值/参数」处理，**只允许三种类型**：

```jsonc
"minEnduranceHours": 4.0                                  // ✅ 数字（推荐）
"isCritical": true                                        // ✅ 布尔
"minEnduranceHours": { "value": 4.0, "unit": "h" }        // ✅ 带单位对象（会加一条 warning）
"minEnduranceHours": "4 小时"                              // ❌ E-PROP-THRESHOLD-STRING
"minEnduranceHours": "4.0"                                // ❌ E-PROP-THRESHOLD-STRING
```

```json
{ "id": "REQ-CRUISE-ENDURANCE", "kind": "Requirement", "name": "CruiseEndurance",
  "owner": "CoaxialOctoRotor",
  "properties": {
    "text": "巡航时间不低于 4 小时",
    "acceptanceCriteria": "在巡航速度 v 与转速比 eta 的稳态工作点下，满电续航时间 T >= 4.0 h",
    "verifyMethod": "simulation",
    "priority": "high",
    "minEnduranceHours": 4.0
  },
  "relations": [
    { "type": "refines", "target": "REQ-MISSION-ENDURANCE", "rationale": "由任务级续航需求分解而来" },
    { "type": "satisfiedBy", "target": "PART-POWER-CHAIN", "rationale": "由功率链的设计参数保障" }
  ] }
```

### 4.4 `ActionDefinition` —— 功能 / 动作

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `inputs` | array | **是** | 可为空数组；每项 `{name(必填), typeRef?, unit?}` |
| `outputs` | array | **是** | 同上 |
| `description` | string | 否 | 人读说明 |

> ⚠️ **注意 `typeRef` 在这一层是「值类型名」**（如 `"Real"`），是个**自由字符串**，
> **不参与引用完整性检查**——这与 `PartUsage.typeRef`（元素引用）完全不同，别搞混。
> 端口 `name` 在同一个数组内不能重复。

```json
{ "id": "ACT-SIM-ENDURANCE", "kind": "ActionDefinition", "name": "EnduranceSimulationRun",
  "owner": "CoaxialOctoRotor",
  "properties": {
    "description": "续航仿真工况。",
    "inputs":  [ { "name": "cruiseSpeed", "typeRef": "Real", "unit": "m/s" },
                 { "name": "speedRatioEta", "typeRef": "Real" } ],
    "outputs": [ { "name": "enduranceHours", "typeRef": "Real", "unit": "h" } ]
  },
  "relations": [ { "type": "verifies", "target": "REQ-CRUISE-ENDURANCE", "rationale": "直接验证续航指标" } ] }
```

### 4.5 `StateDefinition` —— 状态机

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `states` | array of identifier | **是** | 非空、不重复 |
| `initial` | identifier | 否 | 初态，**必须在 `states` 里** |
| `transitions` | array | 否 | 每项 `{from(必填), to(必填), trigger?, guard?}` |
| `description` | string | 否 | 人读说明 |

`transitions` 的 `from` / `to` **都必须出现在 `states` 里**（`E-STATE-TRANSITION-ENDPOINT`）。

```json
{ "id": "STATE-FLIGHT-MODE", "kind": "StateDefinition", "name": "FlightModeStates",
  "owner": "CoaxialOctoRotor",
  "properties": {
    "states": ["Grounded", "Climbing", "Cruising", "Returning", "Landing"],
    "initial": "Grounded",
    "transitions": [
      { "from": "Grounded",  "to": "Climbing",  "trigger": "takeoff command" },
      { "from": "Climbing",  "to": "Cruising",  "trigger": "altitude reached" },
      { "from": "Cruising",  "to": "Returning", "trigger": "reserve energy reached" }
    ]
  } }
```

### 4.6 `Attribute` —— 数值属性（参数）

| 子字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `valueType` | enum | **是** | `Real` / `Integer` / `Boolean` / `String` |
| `defaultValue` | number / integer / boolean / string | 否 | **类型必须与 `valueType` 匹配**（`E-ATTR-DEFAULT-TYPE`） |
| `unit` | string | 否 | **单位单独成字段，非空**——不许写进数值字符串 |
| `description` | string | 否 | 人读说明；**MVP 里公式写在这里**（正式 `Constraint` 元素是二期） |

```json
{ "id": "ATTR-BATTERY-CAPACITY", "kind": "Attribute", "name": "batteryCapacityWh",
  "owner": "PART-BATTERY-PACK",
  "properties": { "valueType": "Real", "defaultValue": 1200.0, "unit": "Wh",
                  "description": "电池包标称容量 E_batt。" } }
```

## 5. `relations` —— 关系

每项**三个字段全必填**（少一个报 `E-REL-FIELD-MISSING`）：

```json
{ "type": "refines", "target": "REQ-MISSION-ENDURANCE", "rationale": "由任务级续航需求分解而来" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | enum | **是** | 5 个受控值之一（`E-REL-TYPE-INVALID`） |
| `target` | string | **是** | **必须指向模型内已存在的元素 `id`**（`E-REL-TARGET-DANGLING`） |
| `rationale` | string | **是** | 非空（`E-REL-NO-RATIONALE`）。**没理由的追溯关系等于没建立** |

### 五种 `type` 的方向语义

| `type` | 读作 | 常见用法 |
| --- | --- | --- |
| `refines` | **A 细化 B**（A 是更细的那条） | 巡航续航 `refines` 任务级续航 |
| `satisfiedBy` | **A 被 B 满足** | 需求 `satisfiedBy` 结构或功能 |
| `decomposes` | **A 分解为 B** | 整机 `decomposes` 功率链；上层功能 `decomposes` 下层功能 |
| `verifies` | **A 验证 B** | 仿真工况 `verifies` 需求（MVP 没有专门的「验证用例」kind，用 `ActionDefinition` 充当） |
| `connects` | **A 连接到 B** | 电池用法 `connects` 电调用法（功率链） |

> **`verifies` 的方向提醒**：是「验证方 → 被验证的需求」。把方向写反了校验不会报错，
> 但 `W-REQ-NO-VERIFY` 的检查是**双向扫描**的，所以不会误报；真正的风险是追溯矩阵读起来别扭。

### `relations` 是可选的

不写 `relations` 字段、或写成空数组 `[]`，都合法。但会触发相应的 warning：

- 需求没有 `satisfiedBy` → `W-REQ-NO-SATISFY`
- 需求标了 `verifyMethod` 却没有任何 `verifies`（双向）→ `W-REQ-NO-VERIFY`
- PartDefinition 既没被引用、自己也没关系 → `W-ELEMENT-ORPHAN`
- PartDefinition 没被任何 `PartUsage.typeRef` 用到 → `W-PARTDEF-UNUSED`

## 6. 校验产物：错误码全表

`validate_model_json` 返回 `{ "ok": bool, "errors": [...], "warnings": [...], "schemaLayer": "..." }`，
每条含 `code` / `element` / `message`（另附 `pointer` 方便机器定位）。

### 6.1 errors（`ok=false`，必须清零才能生成）

| 错误码 | 触发条件 |
| --- | --- |
| `E-INPUT-NOT-JSON` | 输入是字符串但不是合法 JSON |
| `E-ROOT-NOT-OBJECT` | 顶层不是对象 |
| `E-SCHEMA-VERSION` | `schema` 不是 `sysml-ir/v1` |
| `E-PACKAGE-INVALID` | `package` 不是合法标识符 |
| `E-ELEMENTS-NOT-ARRAY` / `E-ELEMENTS-EMPTY` | `elements` 不是数组 / 是空数组 |
| `E-ELEMENT-NOT-OBJECT` | 数组里某项不是对象 |
| `E-FIELD-MISSING` | 缺 `id`/`kind`/`name`/`owner`/`properties`（或顶层 `schema`/`package`/`elements`） |
| `E-ID-INVALID` / `E-ID-DUP` | `id` 不合规 / 重复 |
| `E-KIND-INVALID` | `kind` 不在 6 个受控值内 |
| `E-NAME-INVALID` / `E-NAME-DUP` | `name` 不合规 / 同 owner 下重名 |
| `E-OWNER-INVALID` / `E-OWNER-MISSING` | `owner` 不合规 / 在模型内不存在 |
| `E-PROP-NOT-OBJECT` | `properties` 不是对象 |
| `E-PROP-REQUIRED` | 缺该 kind 的必填子字段（`typeRef`/`inputs`/`outputs`/`states`/`valueType`） |
| `E-PROP-UNKNOWN` | 该 kind 不允许这个子字段（`Requirement` 的阈值字段除外） |
| `E-PROP-TYPE` | 子字段类型不对（含 `quantity` 写成字符串） |
| `E-REQ-NO-TEXT` / `E-REQ-NO-ACCEPTANCE` | 需求缺 / 空白的正文与验收判据 |
| `E-PROP-THRESHOLD-STRING` | **需求阈值写成了字符串** |
| `E-PARTUSAGE-TYPEREF-DANGLING` | `typeRef` 悬空 |
| `E-PARTUSAGE-TYPEREF-WRONGKIND` | `typeRef` 没指向 `PartDefinition` |
| `E-ENUM-INVALID` | `verifyMethod` / `priority` / `valueType` 不在受控枚举内 |
| `E-ATTR-DEFAULT-TYPE` | `defaultValue` 与 `valueType` 不匹配 |
| `E-STATE-STATES-INVALID` / `E-STATE-DUP` | `states` 不是非空数组 / 状态名重复 |
| `E-STATE-INITIAL-NOTFOUND` | `initial` 不在 `states` 里 |
| `E-STATE-TRANSITIONS-INVALID` | `transitions` 不是数组或某项不是对象 |
| `E-STATE-TRANSITION-ENDPOINT` | transition 的 `from`/`to` 不在 `states` 里 |
| `E-REL-NOT-ARRAY` / `E-REL-ITEM-NOT-OBJECT` | `relations` 不是数组 / 某项不是对象 |
| `E-REL-FIELD-MISSING` | 关系项缺 `type`/`target`/`rationale` |
| `E-REL-NO-RATIONALE` | `rationale` 为空 |
| `E-REL-TYPE-INVALID` | `type` 不在 5 个受控值内 |
| `E-REL-TARGET-INVALID` / `E-REL-TARGET-DANGLING` | `target` 不合规 / 悬空 |
| `E-SCHEMA` | 第二层 JSON Schema 交叉检查发现的形状问题（装了 `jsonschema` 才会出现） |

### 6.2 warnings（不拦人，但每条都在说「这里可能有问题」）

| 警告码 | 含义 |
| --- | --- |
| `W-REQ-NO-SATISFY` | 需求没有 `satisfiedBy` 关系 |
| `W-REQ-NO-VERIFY` | 需求标了 `verifyMethod` 但（双向）没有 `verifies` 关系 |
| `W-PARTDEF-UNUSED` | `PartDefinition` 没被任何 `PartUsage.typeRef` 使用 |
| `W-ELEMENT-ORPHAN` | 没被引用且自身也没关系（仅对 `PartDefinition` 提示） |
| `W-CONNECTS-NON-PART` | `connects` 的目标不是结构元素（`PartDefinition`/`PartUsage`） |
| `W-REL-SELF` | 关系的 target 指向自己 |
| `W-NAME-RESERVED` | `name` 与 SysML v2 关键字同名 |
| `W-PROP-UNIT-OBJECT` | 阈值用了 `{value, unit}` 对象形态（合法，提示渲染口径） |
| `W-SCHEMA-UNREADABLE` / `W-SCHEMA-INVALID` | 第二层 Schema 文件读不到 / Schema 自身不合法（已跳过该层） |

### 6.3 `schemaLayer` 字段

如实说明第二层跑没跑：`unavailable`（没装 `jsonschema`）/ `skipped` / `unreadable` / `invalid` /
`ok(+N)`（跑了，额外报了 N 条）。

> 核心规则**全部用纯标准库实现**，因此 `jsonschema` 缺席时功能不减，
> 只是少了这一层交叉检查。

## 7. 渲染：IR 的每个字段落到文本的哪里

`generate_sysml` 的映射（详见 `mcp-server/tools/generator.py`）：

| IR | 生成的 SysML v2 |
| --- | --- |
| `package` | `package <package> { ... }` |
| `PartDefinition` | `part def <name> { ... }`（`isAbstract` → `abstract part def`） |
| `PartUsage` | `part <name> : <typeRef 解析出的 name>;`，`quantity≠1` 时追加 `// quantity: N` |
| `Requirement` | `requirement def <name> { doc /* text */ doc /* 验收判据: ... */ attribute ... }` |
| `ActionDefinition` | `action def <name> { in <name> : <typeRef>; out ...; }` |
| `StateDefinition` | `state def <name> { state X; ... }`，transitions 以 `//` 注释承载 |
| `Attribute` | `attribute <name> : <valueType> = <defaultValue>;  // unit: <unit>` |
| 元素的 `description` | 声明前一行 `// description: ...` |
| `relations` | 元素体内 `// 追溯关系 (relations):` + 每行 `// <srcId> --<type>--> <targetId>  (rationale)` |
| `owner` 是元素 | 该元素**嵌套渲染**在 owner 体内（按 kind 再按 id 排序） |

### 已知的 MVP 简化（不发明无法验证的语法）

以下三处在 SysML v2 里各有正式记法，但 MVP **手头没有可依据的官方样本、也没有可用的官方解析器**
（详见 `docs/T0-调研结论.md`），因此先用注释承载，**语义不丢**（数值仍是数字、单位仍是独立字段），
二期拿到老师样本模型后改成正式语句并补测试：

1. `Attribute.unit` → 行内注释 `// unit: h`
2. `PartUsage.quantity` → 行内注释 `// quantity: 8`
3. `StateDefinition.transitions` → 体内 `// transitions:` 注释块

## 8. 一个可以直接抄的最小完整模型

```json
{
  "schema": "sysml-ir/v1",
  "package": "Demo",
  "elements": [
    { "id": "PART-DEF-MOTOR", "kind": "PartDefinition", "name": "Motor",
      "owner": "Demo", "properties": { "description": "无刷电机。" } },
    { "id": "PART-USE-MOTOR", "kind": "PartUsage", "name": "motorOne",
      "owner": "Demo", "properties": { "typeRef": "PART-DEF-MOTOR", "quantity": 4 } },
    { "id": "REQ-SPEED", "kind": "Requirement", "name": "SpeedRequirement",
      "owner": "Demo",
      "properties": {
        "text": "稳态转速不低于 1000 rpm",
        "acceptanceCriteria": "稳态转速 n >= 1000 rpm",
        "verifyMethod": "simulation",
        "minSpeedRpm": 1000.0
      },
      "relations": [
        { "type": "satisfiedBy", "target": "PART-USE-MOTOR", "rationale": "由电机选型满足" }
      ] }
  ]
}
```

存成 `demo.ir.json` 后：

```bash
cd sysml-modeling-agent/mcp-server
python run_server.py --call validate_model_json --input ../demo.ir.json   # ok: true
python run_server.py --call generate_sysml       --input ../demo.ir.json   # 打印 SysML v2 文本
```
