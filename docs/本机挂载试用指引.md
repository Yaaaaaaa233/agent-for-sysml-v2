### 2.0 先完成落位（一条命令）

因为沙箱限制，**落位这一步需要由有写权限的会话/用户执行**。把下面整段存成
`~/mount-sysml-agent.sh`（或任意位置）后运行 `bash ~/mount-sysml-agent.sh`。
它做四件事：备份 → `cp -R` skill（当时 3 份；二期后 5 份）→ 追加一条 MCP 条目 → 校验（YAML 可解析 / 原条目无损 / 条目数 +1）。
**它不改 `sysml-modeling-agent/` 任何文件，不重启任何进程。**

```bash
#!/usr/bin/env bash
# mount-sysml-agent.sh —— 把 sysml-modeling-agent 挂到本机 DSH（desktop profile）
set -euo pipefail
REPO="<repo>"                              # ← 改成你的仓库绝对路径（如 $HOME/sysml-modeling-agent）
DSH="${DSH_HOME:-$HOME/.dsh}"
PROFILE="${DSH_PROFILE:-desktop}"          # 本机实测运行中会话 = desktop

SKILLS="$DSH/skills"
PY="$REPO/.venv/bin/python"; SERVER="$REPO/mcp-server/run_server.py"; SERVER_CWD="$REPO/mcp-server"
TS="$(date +%Y%m%d-%H%M%S)"

# 0) 基线（!!js 标签必须忽略，否则误报）
chk() { "$PY" - "$1" <<'PY'
import sys, yaml
class L(yaml.SafeLoader): pass
L.add_constructor('tag:yaml.org,2002:js', lambda l, n: '<js>')
doc = yaml.load(open(sys.argv[1], encoding='utf-8'), Loader=L)
assert isinstance(doc, list), "顶层不是数组"
print(f"YAML_OK entries={len(doc)}")
PY
}
[ -f "$CORDIS" ] || { echo "找不到 $CORDIS" >&2; exit 1; }
[ -x "$PY" ]     || { echo "找不到 $PY（先跑 bash $REPO/install.sh）" >&2; exit 1; }
chk "$CORDIS"

# 1) 备份
cp "$CORDIS" "$CORDIS.bak-$TS"; echo "备份 → $CORDIS.bak-$TS"
mkdir -p "$SKILLS"
for n in modeling-workflow element-choice anti-patterns; do
  [ -e "$SKILLS/$n" ] && cp -R "$SKILLS/$n" "$SKILLS/$n.bak-$TS" && echo "已存在 $n → 备份 $SKILLS/$n.bak-$TS"
done

# 2) 复制 skill（当时 3 份；二期后 5 份。cp -R，按任务书要求用真实副本而非符号链接）
for n in modeling-workflow element-choice anti-patterns; do
  rm -rf "$SKILLS/$n"; cp -R "$REPO/skills/$n" "$SKILLS/$n"; echo "挂载 $SKILLS/$n"
done

# 3) 追加一条 MCP 条目（原有内容一字不动）
cat >> "$CORDIS" <<EOF

# --- sysml-modeling-agent 本机 MCP 挂载（${TS}）---
- id: mcp-sysml-agent
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: sysml-agent
    transport: stdio
    command: $PY
    args: ['$SERVER']
    cwd: $SERVER_CWD
EOF

# 4) 校验：YAML 可解析 + 原条目无损 + 条目数 +1
chk "$CORDIS"
"$PY" - "$CORDIS.bak-$TS" "$CORDIS" <<'PY'
import sys, yaml
class L(yaml.SafeLoader): pass
L.add_constructor('tag:yaml.org,2002:js', lambda l, n: '<js>')
old = yaml.load(open(sys.argv[1], encoding='utf-8'), Loader=L)
new = yaml.load(open(sys.argv[2], encoding='utf-8'), Loader=L)
assert new[:len(old)] == old, "原有条目发生变化！"
assert len(new) == len(old) + 1, f"条目数 {len(old)} -> {len(new)}"
print(f"ORIGINAL_INTACT {len(old)} -> {len(new)} OK"); print("新条目 =", new[-1])

diff "$CORDIS.bak-$TS" "$CORDIS" || true
echo "== 挂载完成 TS=$TS =="
```

**提示词 1（主场景：新增一条需求）**

> 用 `docs/demo/step0-before.ir.json` 作为起点，给共轴八旋翼加一条需求：巡航时间不低于 4 小时。

*预期行为（按 modeling-workflow 九步 SOP + 服务器 instructions 固定顺序）*：

1. 加载 `modeling-workflow` skill（可要求它口述九步，验证 skill 真的被读到）；
2. **`mcp__sysml-agent__query_model` 先查现状**：确认 `REQ-CRUISE-ENDURANCE` 这个 id 没被占用、
   有没有同名/同类需求（demo 的 step1 就是这么干的）；
3. 产出/修改 **IR JSON**（`schema: sysml-ir/v1`）：新增一个 `Requirement`，
   带 `acceptanceCriteria`（如「稳态工作点下满电续航 T ≥ 4.0 h」），阈值写成**数字**（`4.0`）而不是字符串；
   必要时补元素内的 `relations`（关系是**挂在元素里**的，不是顶层数组）：
   `{"type": "satisfiedBy", "target": "PART-BATTERY-PACK"}`，或给既有 `ACT-SIM-ENDURANCE`
   补 `{"type": "verifies", "target": "REQ-CRUISE-ENDURANCE"}`；
4. **`mcp__sysml-agent__validate_model_json`** → 一直改到 `errors` 为空；
5. **`mcp__sysml-agent__generate_sysml`** → 得到确定性 SysML v2 文本（同输入同输出，带 `sha256`）；
6. **`mcp__sysml-agent__verify_sysml`** → 回验（声明数与 IR 元素级比对）；
7. 汇报：新增了什么、校验/回验数字、文本在哪、**还有什么没确认**（例如巡航速度与转速比的标称工作点）。

*判据*：**顺序不能乱**——先 query、再 JSON、再 validate、再 generate。
若它跳过 query 直接产 JSON，或在校验报错时去**手改生成的文本**而不是改 JSON，即为违反 SOP。

---

**提示词 2（只查场景：只用 `query_model`，不该产出任何模型）**

> 不改模型，只查：现在这个模型里有哪些需求还没有被任何元素满足？`REQ-CRUISE-ENDURANCE` 被哪些元素引用了？
> （模型用 examples/golden-coaxial-power-chain/golden-coaxial-power-chain.ir.json）

*预期行为*：只调 `mcp__sysml-agent__query_model`（可能两三次不同的查询参数：
`unsatisfied_requirements: true`、`referrers_of: "REQ-CRUISE-ENDURANCE"`，字段名以 `--list-tools` 的
inputSchema 为准：`model` 必填，另有 `keyword`/`query`/`kind`/`referrers_of`/`duplicates`/`unsatisfied_requirements`/`details`/`limit`），
**不产出 JSON、不调用 `generate_sysml`**，直接把结果表格化。
*判据*：工具调用集合 ⊆ {`query_model`}；答案里给出的 id/引用者必须能在返回结果里对上。

**提示词 3（防重场景：重复诉求不能静默新建）**

> 再帮我加一条需求：巡航时间不低于 4 小时。
> （模型用 examples/golden-coaxial-power-chain/golden-coaxial-power-chain.ir.json，它**已经**有这条需求）

## 4. 已知边界与排查

1. **工具对模型的可见名是 `mcp__sysml-agent__<工具名>`**。当时实测 **4 个**：
   `validate_model_json`、`generate_sysml`、`query_model`、`verify_sysml`；
   **二期后是 8 个**，再加 `patch_model`、`traceability`、`parse_sysml`、`export_simulink`
   （以 `run_server.py --list-tools` 为准）。
2. **DSH 没有官方 skill 卸载命令**（`dsh --help` / `dsh plugin --help` 里都没有 skill 子命令），
   卸载 = **手动删目录**（见 §3②）。也没有官方 skill 安装命令，「挂 skill」就是往被监视的根目录放文件。
3. **skill 立即生效，MCP 工具不是**：前者目录被监视（下一个模型步骤刷新）；
   后者在 harness 启动时装载 → **新开会话**；仍旧看不到就**由用户重启 DSH 应用**。
   `failOnStartupError` 默认 `false`：即使本条目连不上，harness 也会正常启动，只是**不出现这些工具**（当时 4 个 / 现 8 个）
   并记一条错误——所以「工具没出现」不等于「DSH 崩了」。
4. **若工具没出现，按这个顺序查**：
   ① profile 改对了没（本机 = `desktop`；用 `env | grep DSH_PROFILE` 复核）；
   ② `cordis.yml` 是否 YAML 合法（用 §3① 的校验片段，注意 `!!js` 标签）；
   ③ 新会话试过没；④ 重启应用（**用户操作，本指引领不做**，红线：不杀不重启 DSH 进程）；
   ⑤ 手工验服务器本体：`… .venv/bin/python mcp-server/run_server.py --list-tools`（与 DSH 无关，必过）。
5. **`desktop` profile 由 Electron 应用独占管理**（T0 §1.5 实测：`dsh --profile desktop --dump-config`
   被拒，`error: profile "desktop" is managed exclusively by the Electron application`）。
   `profiles/desktop/cordis.yml`（61 KB / 208 条）是**组合后的插件树**，
   `cordis.patch.yml` 才是「用户覆盖层」。
   ⚠️ **风险**：应用升级/重装/重新组合依赖时**可能重写 `cordis.yml`**，把追加的条目冲掉。
   如果重启后发现条目消失：把同样的条目改写进 `profiles/desktop/cordis.patch.yml` 的
   `- insert:` 列表（`web/cordis.patch.yml` 里就有这种形态的实例），
   **但本次未做这一步**，且红线只允许改 `cordis.yml` 一处，故留作用户决策。
6. **路径强绑定本机**：`command`/`args`/`cwd` 都写死了
   `<repo>/…`。
   仓库一旦移动/改名，必须同步改 `cordis.yml`；换机重挂请重跑 `install.sh` 再跑 §2.0 脚本
   （脚本里路径写死，换机要改 `REPO`）。路径含中文已实测无碍（stdio 冒烟即从该 cwd 起）。
7. **stdio 不需要 token、不需要公网**：本机试用只走 stdio，全程回环。
   `--auth-token` 仅 `streamable-http`（扣子/云端轨）才校验。
8. **服务器能力边界**（诚实口径，来自 T0 §2.4）：`verify_sysml` 是**自研轻量 lint + 声明抽取 + IR 元素级比对**，
   **不宣称**等同于官方 SysML v2 解析器；它抓「生成器写坏了 / IR 与文本不一致」，
   不抓 SysML 语义合法性（类型可见性、元素位置合法性等）。解析底座换官方实现留二期。
9. **本次未验证的最后一步**：**「DSH 侧真的调用 `mcp__sysml-agent__generate_sysml` 成功一次」未完成**——
   因为条目还没写进 `cordis.yml`。已完成的是：协议链路（stdio `initialize`+`tools/list` 实测 OK）、
   配置条目的形态（与官方 README 示例逐字段对齐）、以及落位脚本的彩排（208→209、原条目无损、可回滚）。
   落位后请在**新会话**里用 §2.2 的提示词 1 做首次实测，并记下工具调用序列。
