# 建模过程记录契约（`sysml-viz-history/v1` → `sysml-timeline/v1`）

> 版本：v1（2026-10-19，与 DSH 插件 `dsh-sysml-viz` v0.1.4、`mcp-server/tools/timeline.py` 同步）
> 定位：回答"这个系统是怎么一步步被完善的、每一轮对话各加了什么"。**IR 仍是唯一事实源**；
> 过程记录是**旁路**（只读 IR 的投影 + 快照），不参与生成/校验，也不反写 IR。

## 1. 为什么需要它

IR 只有"当前状态"，没有"演化历史"：

- `patch_model` 的 `diff` 是**单次调用内**的变更，不跨会话保留；
- IR 本身不记 revision/时间（只有生成器的 sha256）；
- 右栏"模型视图"只能显示当前快照，20 秒的 `+N 新增` 一过就看不出"上一轮改了什么"。

所以 v0.1.4 增加一个**按工作区的过程记录**：每次 IR **语义内容**变化记一步，并把当时完整 IR
存成快照；再由 `timeline.py` 渲染成按步骤着色的 SVG。这样"过程"既能面板查看，也能导出成
一张图放进验收/答辩材料。

## 2. 生产者：DSH 插件 `dsh-sysml-viz`（host 半边）

- 触发：每次 `/api/sysml-viz/model` 加载（含缓存命中）时计算语义哈希
  `sha256(stable({schema, package, elements}))`；只有哈希变化才追加一步。**纯格式/缩进改动不记步。**
- 位置：`<workspace>/.sysml-viz/history/`（工作区由 tab 请求的 `?sessionId=` →
  `~/.dsh/storages/workspace.json` 定位；无 session 时退回模型文件旁）。
- 写入（同步、原子 rename，失败只记日志，不影响模型路由）：

```
<workspace>/.sysml-viz/history/
├── index.json                       # sysml-viz-history/v1（见 §3）
├── step-0000-<rev8>.ir.json         # 第 0 步完整 IR 快照
├── step-0001-<rev8>.ir.json
└── timeline.svg                     # 派生文件，可随时重生成
```

- 清空：`DELETE /api/sysml-viz/history` 只删 `.sysml-viz/history/`，不动 IR；清空后当前模型
  重新记为基线。
- 关闭：host config `history: false` / 环境变量 `SYSML_VIZ_HISTORY=0`。

## 3. `index.json`（schema = `sysml-viz-history/v1`）

```json
{
  "schema": "sysml-viz-history/v1",
  "workspace": "/abs/ws",
  "modelPath": "/abs/ws/model-output/<pkg>/<pkg>.ir.json",
  "createdAt": "2026-10-19T12:48:53.995Z",
  "updatedAt": "2026-10-19T12:51:12.900Z",
  "provenance": { "kind": "session-log-reconstruction", "sessionId": "...", "method": "..." },
  "steps": [
    {
      "seq": 0,
      "at": "2026-10-19T12:48:53.995Z",
      "revision": "98713da0",
      "irSha256": "<64hex>",
      "semanticSha256": "<64hex>",
      "elements": 1,
      "relations": 0,
      "added": [],
      "removed": [],
      "changed": [],
      "source": "baseline",
      "sessionId": "a89d8bff",
      "turn": null,
      "note": "基线（会话开始时的最小骨架）",
      "snapshot": "step-0000-98713da0.ir.json"
    }
  ]
}
```

字段口径：

| 字段 | 含义 |
| --- | --- |
| `seq` | 步骤序号，从 0 开始；0 为基线 |
| `revision` | IR 文件**原文** sha256 前 8 位（与右栏 `rev` 一致） |
| `irSha256` | 快照文件原文 sha256（全文） |
| `semanticSha256` | `{schema,package,elements}` 规范化 JSON 的 sha256；去重用 |
| `added` / `removed` / `changed` | **相对上一步**的元素 id；`changed` 指同 id 但元素内容变了 |
| `source` | `baseline` / `change`；从会话日志事后重建的步骤为 `session-log`（UI 标「日志重建」） |
| `sessionId` | 写入该步时会话短 id（host 从 tab 请求 `?sessionId=` 得到；无法精确到对话轮次） |
| `turn` | 可选：对话轮次（仅重建/显式记录时有；`timeline.py` 图例优先显示「第 N 轮」） |
| `note` | 可选：人读备注 |
| `snapshot` | 快照文件名（缺文件时 `timeline.py` 用相邻快照并给 `W-SNAPSHOT-MISSING`） |

快照文件就是**当时的完整 IR**（`sysml-ir/v1`），用于画每一步的元素集合与内容差异；不保证
与快照时刻的 `.sysml` 文本逐字节对应（文本是派生文件，可能尚未生成）。

## 4. 消费者

### 4.1 右栏「过程」面板（client 半边）

- `GET /api/sysml-viz/history?sessionId=` 返回 `{available, steps, current, session}`；
  `session.addedIds` = 该会话所有步骤的 `added ∪ changed`，用于 header `本会话 +N` 与图上持久描边。
- `GET /api/sysml-viz/timeline.svg?sessionId=` 调 `timeline.py` 渲染 SVG（同源 `<img>` 展示）。

### 4.2 `mcp-server/tools/timeline.py`（纯标准库）

```bash
python mcp-server/tools/timeline.py --history <dir> [--out <svg>] [--title ...] [--json] [--check]
```

- `load_history(dir)` → 校验 index；`build_timeline(history, snapshots)` → 纯函数数据；
  `render_svg(timeline, opts)` → **确定性** SVG（同输入 + 同 `generated_at` 逐字节一致）；
  `export_timeline(dir, out_path=None, title=None, generated_at=None)` → 永不抛异常，返回
  `{ok, schema:"sysml-timeline/v1", svgPath, summary, steps, errors, warnings}`。
- 图内容：最终系统生长树（节点颜色 = 元素首次出现步骤；被修改过的节点加 `△<步>`）、右侧每步图例
  （时间/会话/轮次/`+a ~c -r`/新增元素名）、底部元素数曲线。
- 错误码：`E-HISTORY-NOT-FOUND` / `E-HISTORY-SCHEMA` / `E-NO-STEPS` / `E-WRITE`；
  快照缺失/损坏降级为 `W-SNAPSHOT-*` 仍出图。

### 4.3 MCP 工具 `export_timeline`（`run_server.py` 第 9 个工具）

入参：`history_dir?` / `model_path?` / `output?` / `title?`（都可选）；`history_dir` 不传时从
`SYSML_VIZ_HISTORY` → `model_path` 所在目录 → 当前工作目录逐级向上找 `.sysml-viz/history`。
本地模式示例：

```bash
python mcp-server/run_server.py --call export_timeline \
  --input '{"history_dir": "model-output/.sysml-viz/history"}'
```

## 5. 诚实性边界（必须一起读）

1. **拉取式**：只有模型视图 tab 在轮询（或某次请求触发模型加载）时才落步骤；没有 tab 打开期间的
   多次变化会合并成下一次观察到的一步。不是后台常驻监听。
2. **会话归属是启发式**：host 只知道 tab 请求的 `?sessionId=`，不知道 DSH 的对话轮次；跨会话改动
   归到请求方会话。要精确到"第几轮"，需在写入时显式给 `turn`（如 `provenance` 重建）。
3. **事后重建不等于实时记录**：从 DSH 会话日志重建的步骤标 `source:"session-log"`，且 index 里
   `provenance` 必须写清来源与方法（本仓库 Q2 演示的 5 步就是这样来的，见 `proposal/新功能可行性方案.md` §3.13）。
4. **快照不自动清理**：每步一份 IR，长跑后目录会变大；需要归档策略时另加（当前按工作区手动清理）。
5. **它不是 MSOSA 的"模型历史"**：MSOSA 侧只有导入后的当前项目状态；本记录是 DSH 侧的旁路证据，
   两者不可互相替代。
