## 0. 一页结论

| 问题 | 结论 | 置信度 |
| --- | --- | --- |
| ① skill 落在哪、什么格式 | **`~/.dsh/skills/<name>/SKILL.md`**（或平铺 `<name>.md`），YAML frontmatter 必填 `name` + `description`。另有项目级与共享级根目录，见 §1.2 | **高**（读到 DSH 自身随包文档） |

### 1.2 ① skill 目录的注册 / 发现方式

来源：`@deepseek-ai/dsh-skill-filesystem` 的随包 README（原文摘录，rank 表照抄）。

**发现根目录（按 rank 顺序扫描）**

| Rank | 来源 | 路径 |
| --- | --- | --- |
| 100 | `project-dsh` | `<projectRoot>/.dsh/skills` |
| 200 | `project-agents` | `<projectRoot>/.agents/skills` |
| 300 | `custom` | `Config.customSkillDirs` |
| 400 | `user-dsh` | `<dshHome>/skills` ← **即 `~/.dsh/skills`** |
| 500 | `user-agents` | `<agentsHome>/skills` ← 即 `~/.agents/skills` |
| 600 | `bundled` | `bundledSkillDir`（随包提供） |

- `<projectRoot>` = 包含 `.git` 的最近祖先目录；**没有 `.git` 时用当前 cwd**。
- 用户 DSH 根目录会跳过其 `.system` 子目录。
- 本机实测：`DSH_HOME=~/.dsh`；本工作区 `2610_MBSE` **不是** git 仓库（`git rev-parse` 返回 `fatal: not a git repository`）。

**格式要求（原文口径）**

- skill 可以是被扫描根目录**顶层**的目录 bundle `<name>/SKILL.md`，也可以是**平铺文件** `<name>.md`；
  **刻意不支持**递归发现 `**/SKILL.md`。
- 文件以 YAML frontmatter 开头：**必填 `name` 与 `description`**，可选 `whenToUse`、`metadata`、
  `disable-model-invocation`、`user-invocable`。`disable-model-invocation: true` 会把 skill 从
  面向模型的目录里排除。
- 目录与正文生命周期独立：**每次加载都会重新读取当前文件**，编辑正文无需重启。
- 根目录被**监视**：新增 / 改名 / 删除 skill 会在下一个模型步骤触发目录刷新，无需重启。

**补充约束**（`@deepseek-ai/dsh-skill-filesystem` 包文档口径）：frontmatter 的 `name`
**必须是 kebab-case**（小写字母/数字，用 `-` 连接）；
非法名字的 skill 不会被加载（按名字精确查找时返回「无此 skill」而不是抛错）。
因此本项目的三份 skill 目录名一律取 `modeling-workflow` / `element-choice` / `anti-patterns`。

**实测印证**：`~/.dsh/skills/` 下的既有 skill 有两种落位——`media-downloader/`（真实目录，含
`SKILL.md` + `scripts/`）与 `academic-paper` 等（**符号链接**指向 `~/.dsh/skill-sources/...`）。
说明「符号链接目录」是官方支持的常态做法（README 亦明说「符号链接目录和扁平文件都能作为普通文件预览」）。

**对本项目的落位方案（已写进 `install.sh`）**

```
sysml-modeling-agent/skills/<name>/SKILL.md
        └── install.sh 默认建立符号链接到  $DSH_HOME/skills/<name>
            （$DSH_HOME 未设置时回退 ~/.dsh）；--copy 则改为复制。
```

> ⚠️ **未确认项**：本机 `--dump-config` 被拒——`error: profile "desktop" is managed exclusively by
> the Electron application`。因此**桌面端 profile 的活动配置无法用 CLI 转储**，§1.3 的结论来自
> 随包 README.zh.md 的字段表与最小配置示例（实机 `cordis.yml` 里没有该条目，**挂载未验证**），
> 而非 `--dump-config-schema`。这不影响 skill 落位（skill 根目录与
> profile 无关），但若老师要改桌面端 profile 的插件条目，只能走 GUI 或手工编辑 `cordis.yml`。

### 1.3 ② 工具 / MCP 的注册方式

来源：随包文档 `@deepseek-ai/dsh-mcp-client/README.zh.md` 的「最小配置」示例与字段表（原文摘录）；
实机 `~/.dsh/profiles/*/cordis.yml` 中**没有** `@deepseek-ai/dsh-mcp-client` 条目（**挂载未验证**）。

**配置文件**：`$DSH_HOME/profiles/<profile>/cordis.yml`（实机为 `~/.dsh/profiles/desktop/cordis.yml`）。
每台 MCP 服务器加一条插件条目：

```yaml
- id: mcp-sysml-agent                  # 条目 id（本方案自拟）
  name: '@deepseek-ai/dsh-mcp-client'  # 插件包名（照抄，勿改）
  config:
    serverName: sysml-agent            # 工具命名空间；[A-Za-z0-9_-]{1,32}
    transport: stdio
    command: python
    args: ['run_server.py']
    cwd: /path/to/sysml-modeling-agent/mcp-server
```

远端 / 容器化部署用 Streamable HTTP：

```yaml
- id: mcp-sysml-agent
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: sysml-agent
    transport: streamable-http
    url: http://localhost:8000/mcp
    headers:
      Authorization: !!js '`Bearer ${process.env.MCP_TOKEN}`'
```

**关键字段（照抄 README 字段表）**

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `transport` | **必填** | `stdio` 或 `streamable-http` |
| `serverName` | **必填** | 服务器工具名称的 namespace；`[A-Za-z0-9_-]{1,32}`，一个注册作用域内唯一 |
| `command` / `args` / `env` / `cwd` | — | stdio：可执行文件、参数、额外环境变量、工作目录 |
| `url` / `headers` | — | streamable-http：端点 URL 与额外请求标头 |
| `toolCallTimeoutMs` | `60,000` | 每次 `tools/call` 的超时 |
| `maxInstructionBytes` | `32,768` | 服务器 instructions（含归属说明）的 UTF-8 字节上限；超限直接拒绝连接 |
| `failOnStartupError` | `false` | 初始连接失败时是否拒绝插件激活 |
| `reconnect.*` | 开启 | 自动重连（500 ms 起翻倍，上限 30 s，最多 10 次） |

**对模型可见的工具名**：`mcp__<serverName>__<rawName>`，例如本项目的
`mcp__sysml-agent__validate_model_json`、`mcp__sysml-agent__generate_sysml`、`mcp__sysml-agent__query_model`。

**对 `run_server.py` 契约的印证（重要）**

README 明说「本地程序使用 stdio，远端服务使用 Streamable HTTP」。我们契约里的
`--transport stdio|streamable-http` 与之一一对应，`--auth-token` 落在 `headers.Authorization` 上，
**只有 streamable-http 需要校验**——契约与 DSH 的实际行为完全吻合，无需改动。

> **做到哪一步了（诚实标注）**：
>
> - ✅ **服务端侧已实测跑通**：用真实 MCP 客户端（Streamable HTTP）完成
>   `initialize` → `tools/list` → 4 次 `tools/call`，并验证 `--auth-token` 的 401 行为
>   （含「超集 token 不被前缀匹配接受」这一边界）。原始输出见
>   `docs/probe-mcp-http/EVIDENCE.txt`，复现命令见 `docs/T6-演示记录.md` §7.2。
> - ⚠️ **仍未做到的**：**把本项目真的挂进 DSH 跑一次**。MCP 条目要写进
>   `~/.dsh/profiles/desktop/cordis.yml`，而该文件属于 DSH 配置，本次调研承诺「只读、不得修改」；
>   且桌面端 profile 由 Electron 独占管理。因此「DSH 侧成功调用
>   `mcp__sysml-agent__generate_sysml` 一次」**仍是未验证项**，
>   建议由老师/队员在开发轨上手工加条目后实测一次（配置片段见 §1.3 与 `install.sh` 输出）。

### 1.4 ③ 打包安装惯例

**DSH 的扩展单元是 npm 包，不是 zip/目录包。**

实机 profile 目录 `~/.dsh/profiles/desktop/`：

```
package.json          # dependencies + "dsh": { "profile": { "bundles": [...] } }
cordis.yml            # 组合后的插件树（自动生成，约 61 KB）
cordis.patch.yml      # 用户覆盖层（插件开关只改这里最后一条匹配覆盖项的 disabled）
pnpm-workspace.yaml   # packages: ['.']，nodeLinker: hoisted
pnpm-lock.yaml
node_modules/
```

- **分发**：`dsh plugin --profile <name> add <package-spec>`（底层就是 `pnpm add`）。
  也支持本地路径 / tarball / git spec——实机 `package.json` 里就有
  `"dsh-orb": "file:~/Documents/DSH/plugins/dsh-orb-0.1.7+mascot.1.tgz"` 这样的写法，
  证明**本地 `.tgz` 是受支持的正式分发形态**。
- **组合包选择**：`dsh.profile.bundles` 是有序列表，决定配置优先级。
- **更新**：`git pull` / 重新 `add` + 新版号。
- **`--patch <path>`**：启动时可叠加额外 patch 层（可重复），用于不改动 profile 主配置的临时挂载——
  这是**开发期挂 MCP 的最轻做法**，推荐给队员自测用。

**对本项目的落位方案**

```
sysml-modeling-agent/           ← git clone 下来，整包可搬运
├── skills/                     → 符号链接/复制到 $DSH_HOME/skills/
├── mcp-server/                 → 在 DSH 里注册为一条 dsh-mcp-client 条目（stdio）
├── knowledge/ examples/ tests/
└── install.sh                  → 建 venv、装依赖、打印上述两步的确切指引
```

> **为什么不做成 npm 组合包**：本项目的主体是 Python 工具 + Markdown skill，**没有需要
> 注入宿主进程的 JS 代码**。做成 bundle 只为了「一键 add」，但会把一个 Python 项目硬塞进
> pnpm 依赖图。方案 8.1 的取向是「能力包与宿主解耦，一包做出来到处挂得上」——当前形态
> 恰好满足：三个资产（skill / MCP 服务 / 知识库）都是可搬运的独立资产。
> **规范化的一键安装（T12）留二期**，届时若确有必要再包一层 bundle。

## 2. 解析底座选型

### 2.1 判据（方案 5.4 / 9.1-T0 给定）

1. **能否在本机跑通**；
2. **能否给出带位置的语法错误**；
3. **许可协议是否可用**。

### 2.2 候选 A：官方 pilot implementation（`Systems-Modeling/SysML-v2-API-Services`，Java）

```
$ java -version
The operation couldn't be completed. Unable to locate a Java Runtime.
Please visit http://www.java.com/en/installation.html to install Java.
$ command -v gradle mvn
（无输出）
```

**结论：本机无 Java 运行时、无 Maven/Gradle → 判据 1 不满足，直接出局。**
官方实现是 Java + Spring Boot + Gradle 体系，装 JDK 17+ 与构建工具可跑，但：
- 引入一个 JVM 工具链到「Python 工具服务」里，部署面显著变重；
- 云端轨（扣子）对单次工具调用有超时上限（方案 8.5），JVM 冷启动不利；
- **留二期**：若老师样本模型需要用官方解析器权威回验，届时按 §2.5 的薄适配层替换实现。

### 2.3 候选 B：PySysML2（`DAF-Digital-Transformation-Office/PySysML2`）

**可得性：能装上。**

```
$ python3 -m pip download --no-deps PySysML2
ERROR: Could not find a version that satisfies the requirement PySysML2 (from versions: none)
→ 不在 PyPI 上。改从 GitHub 装：

$ python3 -m pip install "git+https://github.com/DAF-Digital-Transformation-Office/PySysML2"
Resolved https://github.com/.../PySysML2 to commit 6dfaf83ebe8abe2c988a178e105e73c7e9c56fdf
Successfully installed ... pysysml2-0.1.1 ...
```

- **许可**：Apache License 2.0 → 判据 3 **满足**。
- **依赖**：`anytree` / `graphviz` / `numpy` / `pandas` / `openpyxl` / `antlr4-python3-runtime==4.10` / `typer==0.7.0`。
  为拿一个解析器拖进 pandas + numpy，代价偏重。

**判据 1（能否跑通）：打折扣。**

- `pysysml2` **CLI 不可用**：`TypeError: TyperArgument.make_metavar() takes 1 positional argument but 2 were given`
  ——typer 0.7.0 与环境的 click 8.5.0 不兼容。
- 只能用其库 API 直连 ANTLR（`SysML2Lexer` / `SysML2Parser`），且启动时持续告警
  `ANTLR runtime and generated code versions disagree: 4.10!=4.13.2`——**运行时与生成代码版本不一致**，
  是隐患。

**判据 2（带位置的语法错误）：满足。** ANTLR 的 `syntaxError` 回调给出 `line:col`：

```
line 2:4 mismatched input 'requirement' expecting {...}
line 3:36 no viable alternative at input 'attributecapacityWh:Real='
```

**但真正致命的是覆盖面。** 该实现的语法是一份**很窄的手写子集**（`pysysml2/grammar/SysML2.g4` 仅 331 行；
官方 SysML v2 语法是这个量级的两三个数量级）。其**词法关键字表完整共 24 个**（原文照抄）：

```
about actor attribute case comment connection connect def doc from end import include
item message objective package part port ref redefines specializes subject subsets
:: :>> :> to use in out of
```

**没有 `requirement`、没有 `state`、没有 `action`、没有 `satisfy`、没有 `refine`**——而这几样正是
MVP 必须生成的核心产物。

实测（原始输出存 `docs/probe-pysysml2/EVIDENCE.txt`）：

| 输入 | 结果 |
| --- | --- |
| `part def Battery { attribute capacityWh : Real = 1000.0; }` | **1 错**：`no viable alternative at input 'attributecapacityWh:Real='` |
| `requirement def CruiseEndurance { … }` | **2 错**：`mismatched input 'requirement'`（关键字根本不在词法表里） |
| 缺 `}` 的畸形输入 | 只有 1 错，且**不是**括号错——ANTLR 静默插入了 `<missing '}'>`，**错误监听器抓不到未配对括号** |
| `attribute capacityWh : Real;`（**无**默认值） | **0 错** |
| `attribute x : Real = 4.0;`（**有**默认值） | 报错 |

最后两行的对比把问题钉死了：**PySysML2 连「带默认值的类型化属性」这一种写法都表达不了**
（`feature_attribute_def: KW_ATTRIBUTE ID ':' TYPE ';' | KW_ATTRIBUTE ID '=' CONSTANT ';'`
——两种形态二选一，没有 `ID : TYPE = CONSTANT`）。而方案 2.3 自己给出的示例里就有
`attribute minEnduranceHours : Real = 4.0;`。

**用它对本项目生成文本的实测**（`examples/golden-coaxial-power-chain/*.sysml`，150 行）：

```
--- golden.sysml: syntax_errors=14
    line 9:43  no viable alternative at input 'attributebatteryCapacityWh:Real='
    line 16:39 no viable alternative at input 'attributeescEfficiency:Real='
    ...
    line 66:4  extraneous input 'requirement' expecting {'}', 'actor', 'attribute', ...}
```

**14 个错误全部可归因于 PySysML2 的语法缺口**（`requirement` 关键字缺失、带默认值的属性缺失），
**没有一个是模板形态本身的问题**——这一点很重要，它反过来说明我们的模板没有乱写。

> 说明：这是一次「为诚实而做的体检」。把 `[8]` 数量记法从模板里拿掉、改用
> `part escUnit : ElectronicSpeedController;  // quantity: 8`，正是因为连它也无法验证——
> 见 §2.4 的选型纪律。

### 2.4 选定方案

> **MVP 回验底座 = 内置轻量语法自查 lint + 声明抽取 + 与 IR 的元素级比对**
> （`mcp-server/tools/sysml_lint.py`，纯标准库，零依赖）；
> **官方解析器（Java pilot）与 PySysML2 的适配统一留二期**。

**理由**

1. 两个候选都不满足本期判据：Java 系**跑不起来**；PySysML2 **装上但拒收我们的核心产物**
   （实测 14 个错误），且随包语法缺口无法绕开。
2. 自己写这一层**成本很低且可控**：它要抓的不是「SysML v2 语义是否成立」，而是
   「**生成器有没有写坏**」和「**IR 与文本是否一致**」——这恰好是方案 2.3 第 4 步说的
   「解析成功后再与原始 IR 做元素级比对」。lint 能给出 `line:column` + 出错行原文，满足判据 2。
3. **零依赖**意味着 Windows 部署机上不会因为解析器装不上而断链（方案 8.5 的「解析底座不稳定」风险）。
4. **留了替换口**：回验是一个薄适配层（`lint_sysml` / `extract_declarations` / `roundtrip_check`
   三个函数），二期把官方解析器包进来只换实现、不动上层契约。

**能力边界（诚实标注，已写进模块 docstring）**

- ✅ 能抓：括号/注释/字符串未闭合、语句未终结、未知关键字（**全部带行列定位**）、
  声明与 IR 元素的数量与名字不匹配、`typeRef` 渲染错。
- ❌ 不能抓：SysML v2 的语义合法性（类型是否可解析、名字是否在正确的作用域可见、
  `requirement def` 是否能放在这个位置）。
- ❌ **不宣称**等同于官方解析器。方案 10.1 说「架构抬下限不抬上限」，这里如实把「语法正确」的
  保证口径收窄为「**由固定模板保证 + 由结构自查回验**」，而不是「已通过官方解析器」。

### 2.5 二期接入点（预留）

`tools/sysml_lint.py` 顶部即写明替换位置。二期候选：
- 官方 pilot implementation（需先解决 JVM 部署与云端超时问题）；
- 若 PySysML2 后续版本补齐 `requirement` / `state` / `action` 与「带默认值的属性」，
  可作为纯 Python 侧的轻量选项——**接入前必须用本仓库 `docs/probe-pysysml2/` 的探针重跑一遍**。
