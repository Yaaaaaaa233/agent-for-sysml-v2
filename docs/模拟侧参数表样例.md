# 模拟侧参数表样例（`export_simulink`）

> ⚠️ **表中数值均为占位值，非实测结论。** 1200 Wh、240 W、0.95、0.85、0.72、4.0 h
> 等数字全部来自标杆案例 IR 的 `defaultValue`，只用于打通「模型 → 参数 → 仿真」链路。
> 在拿到选型数据、台架数据或试飞数据之前，不得把它们当作续航、效率或功率的
> 实测结论 / 仿真结论引用。

本文是 `export_simulink`（二期 T10）的样例交付物：把
`examples/golden-coaxial-power-chain/golden-coaxial-power-chain.ir.json` 里已有的
参数、公式与需求阈值，实际导出成仿真侧可读的参数表与公式清单。**文中表格与计数均由工具
实际运行产生，不是手写**；命令见 §1，输入文件摘要见 §2。

## 0. 口径：模型事实 / 规范语义 / 推断

| 层次 | 本文能说的 |
| --- | --- |
| **模型事实** | IR 里有哪些 `Attribute`、`Requirement` 阈值、`Constraint`；它们的 name / valueType / unit / defaultValue / owner 路径是什么。这些字段是导出结果的唯一来源。 |
| **规范语义** | 导出格式（CSV 表头、JSON 结构、Markdown 表）和每一行的 `kind` 含义由本仓库的 `export_simulink` 约定；公式文本按 IR 的 `expression` 原样透传，不做代数化简。**不声称**这些 SysML v2 文本或导出结果已由官方解析器确认通过——导出也不代表仿真模型已经跑通。 |
| **推断** | 如何把行装配成 `Simulink.Parameter`、如何把公式行落成计算块 / 约束，属于仿真侧的实现选择；本文只给示意，未在 Simulink 中实测。 |

## 1. 复现命令（实际执行）

```bash
# 以仓库根为工作目录（相对路径：从本文件位置 `docs/` 上跳一级）
cd sysml-modeling-agent

PYTHONPATH="$PWD/mcp-server" .venv/bin/python - <<'PY'
from tools.validator import load_model
from tools.export import export_simulink

model = load_model("examples/golden-coaxial-power-chain/golden-coaxial-power-chain.ir.json")
result = export_simulink(model, fmt="md", scope="all")   # 换成 csv / json 即得其它格式
print(result["content"])
print("rows =", len(result["rows"]), "notes =", len(result["notes"]))
for row in result["rows"]:
    print(row["kind"], row["path"], row["name"])
PY
```

命令行入口同样可用（输出写到标准输出，notes 写到标准错误）：

```bash
PYTHONPATH="$PWD/mcp-server" .venv/bin/python -m tools.export \
  examples/golden-coaxial-power-chain/golden-coaxial-power-chain.ir.json --fmt md --scope all
```

**读表提示**：

- `path` 是 owner 链（含 package）。例如 `CoaxialOctoRotor.PowerChain` 表示该参数
  属于 package `CoaxialOctoRotor` 下的 `PowerChain`；`CoaxialOctoRotor.CruiseEndurance`
  下的行是**需求阈值**，其「所有者」是那条需求，不是部件参数。

  只能当仿真判据 / 校核条件，**不能**直接塞进被控对象参数集。
- `kind=Constraint` 的行是公式清单：`defaultValue` 列放 `expression` 公式文本，

  `EnduranceBudget` 公式为 `T = batteryCapacityWh * usableEnergyFraction / cruisePowerW`；

## 4. CSV 实际输出（表头 + 前 5 行）

CSV 文件带 UTF-8 BOM（Excel / MATLAB 可直接识别中文），行尾为 CRLF；
字段里的逗号、引号、换行由标准 CSV 规则转义。实际内容开头为：


需求阈值行在 CSV 中形如（`extra` 列本身是 JSON，CSV 会把其中的双引号翻倍）：

## 5. 仿真侧如何消费

### 5.1 参数行（`kind=Attribute`）→ `Simulink.Parameter`

MATLAB 侧可直接读 CSV，按 `kind` 过滤后逐行装配。下面只是**示意代码**，
未在 Simulink 工程中实测；真实工程请按自己的数据字典 / 工作区规范调整：

```matlab
T = readtable('params.csv', 'TextType', 'string');   % 文件名仅作示例
attrs = T(T.kind == "Attribute", :);

for i = 1:height(attrs)
    p = Simulink.Parameter(attrs.defaultValue(i));
    p.DataType = attrs.valueType(i);                 % 示意：Real/Integer/... 需再映射到仿真侧类型名
    p.Unit     = attrs.unit(i);                      % 空字符串表示无量纲或未给单位
    p.Description = attrs.path(i) + "." + attrs.name(i);
    assignin('base', attrs.name(i), p);
end
```

要点：

1. **单位是独立列**，不要把它拼进数值字符串；空 `unit` 要人工确认是「无量纲」
   还是「漏填」。
2. `valueType` 直接对应 IR 的 `Real / Integer / Boolean / String`；赋值前按它做一次
   类型核对，避免把 `String` 参数塞进数值端口。
3. `path` 可用于生成变量名前缀或分层数据字典，避免同名参数在不同部件下冲突；
   本工具不擅自把 `.` 替换成 `_`，命名策略留给仿真侧决定。
4. **占位值警告仍然有效**：先替换为选型 / 实测数据，再跑仿真；不要拿这里的
   1200 Wh、240 W、0.95、0.85、0.72 当结论。

### 5.2 公式行（`kind=Constraint`）→ 计算块 / 约束

- `defaultValue` 列（CSV / Markdown）或 `expression` 字段（JSON）是 IR 里的公式
  文本，工具只透传，不做解析、化简或量纲检查。
- `extra` 列（CSV / Markdown）或 `parameters` 字段（JSON）是公式引用的参数名列表；
  导出时已把 Attribute 的元素 id 解析成 `name`（解析不到的保留原 id，并在 `notes`
  里说明）。
- 消费方式：在仿真侧按 `expression` 建计算子系统 / MATLAB Function / 掩码约束，
  或人工翻译成 `Simulink` 的数学运算；**公式行本身不是可赋值参数**。
- 本案例已有 1 条 `Constraint`（`EnduranceBudget`），导出为 1 行公式；工具按通用方式
  读取 `properties.expression` 与 `properties.parameters`，不依赖校验器的 kind 白名单，
  后续新增公式无需改导出代码。

### 5.3 需求阈值行（`kind=RequirementThreshold`）→ 判据 / 边界

- 这些是需求里的数值门槛（如 `minEnduranceHours = 4.0`、`minSpeedRatio = 0.75`），
  不是被控对象参数。建议用于：验收判据、饱和/限幅边界、优化约束、仿真后处理
  的 pass/fail 阈值。
- `extra` 列已标注「需求阈值，非部件参数」；`notes` 里也有同样提示。
- `{value, unit}` 形式的阈值会被拆成 `defaultValue` + `unit` 两列；`valueType` 按
  JSON 里的实际数值类型推断（整数 → `Integer`、浮点 → `Real`、布尔 → `Boolean`），
  所以需求阈值若需要实数语义，请把值写成 `4.0` 而不是 `4`。

### 5.4 三种格式怎么选

| 场景 | 建议 |
| --- | --- |
| MATLAB / Excel 直接读表 | `fmt="csv"`（BOM 已带，`readtable` 可直接识别中文与列名） |
| 程序化处理、保留类型与嵌套字段 | `fmt="json"`（`rows` + `notes`，不丢数值类型） |
| 评审、贴进设计文档 | `fmt="md"`（表格可直接阅读；换行以 `<br>` 表示、`|` 已转义） |

## 6. 本次导出的 notes（`fmt="csv"`, `scope="all"` 实际输出）

1. RequirementThreshold 行是需求阈值，非部件参数；应作为仿真判据 / 校核条件使用。
2. 导出范围 scope=all，格式 fmt=csv。
3. 参数值直接取自 IR 的 defaultValue，可能仍是占位值（非实测结论）；用于仿真前须与选型数据或实测数据核对。
4. CSV 为 UTF-8 BOM + CRLF、表头固定（path,name,valueType,unit,defaultValue,kind,id,extra）；MATLAB 可用 `readtable('params.csv', 'TextType', 'string')` 直接读取（文件名仅作示例）。
5. Simulink 侧建议逐行装配 `Simulink.Parameter`：Value 取 defaultValue，Unit 取 unit，Description 由 path 与 name 拼出，再统一加载到仿真工作区。
6. Constraint 行的 defaultValue 列是公式文本，extra 列是 {"parameters":[...]} 的 JSON；公式行不能直接当参数赋值，需在仿真侧按 expression 建立计算或约束。

## 7. 限制与后续

- **数值真实性**：本文所有数值均为占位值，非实测结论；导出工具不判断物理合理性。
- **不重复校验**：`export_simulink` 不做第二道 `validate_model_json`。缺 `valueType`、
  缺 `defaultValue`、缺 `expression` / `parameters`、阈值写成字符串等情况不会让导出
  失败，而是按空值 / 跳过处理，并把原因写进 `notes`——消费前先看 notes。
- **未提交官方解析器核验**：导出的是表格与公式文本，不构成官方解析器结论；如需
  SysML v2 语法 / 语义结论，请另行调用仓库的官方解析适配层，并以它的实测输出为准。
- **Simulink 侧未实测**：§5.1 的 MATLAB 代码是装配示意，未在真实 Simulink 工程中
  运行；具体数据字典、变量作用域与单位换算需按仿真侧规范落地。
- 当前标杆案例有 1 条 `Constraint`、2 条 `Connection`；`Connection` 是结构连接，
  不属于参数 / 公式 / 阈值，故不产生导出内容。等 IR 增加更多 `Constraint` 后，
  重跑 §1 的命令即可得到新的公式行，无需改本工具。
